### 3. 服务目标、容量与观测契约

<a id="overview--31-sli口径"></a>
#### 3.1 SLI口径

以下是待实现/校准的观测契约，不表示现有Actuator已全部暴露。按部署版本、场景、provider、结果分类；日志关联runId/traceId，指标不使用用户ID、sessionId、完整URL等高基数或敏感标签。

| SLI | 分子/分母或计时边界 | 不能掩盖的失败 |
|---|---|---|
| 请求受理可用率 | 成功返回可核对Run标识的合法请求 / 合法受理请求；从入口至响应 | 网关5xx、过载拒绝、系统异常、未知结果；参数/权限拒绝另计 |
| 首业务事件延迟 | 已受理请求到首个对用户有意义的正文/交互/进度事件；另报run.started延迟 | run.started不是首个模型答案；超时和未产出必须计入失败分布 |
| Run完成率与时间 | 按provider/模式统计应完成Run的正确终态及持续时间 | WAITING_USER/ASYNC_WAITING分开统计，不把等待态算答案成功；用户取消单列 |
| 结果恢复成功率 | FULL恢复请求在约定期限内读齐已持久化范围且顺序/去重正确 / 有恢复需求请求 | 终态已入DB但前端未消费；no-store业务事件不纳入可回放承诺 |
| Stop本地收口 | 活动Run从接受Stop到合法终态及资源释放；自然完成已竞胜单列。WAIT取消另量Interaction/Binding及实际续跑Run收口 | 历史WAIT Run不要求改写CANCELLED；HTTP返回不等于远端已停，远端确认独立指标 |
| 数据正确性 | 重复活动Run、越代写入、重复终态、已提交事实丢失、错误跨Run取消数量 | 正确性指标不能被平均延迟或HTTP200替代 |
| 服务RTO/任务RTO | 分别从故障开始到服务恢复、存量任务全部按策略收口 | 接口恢复但遗留RUNNING未处理不能宣布完全恢复 |
| RPO | 按已提交事实、实时事件、外部副作用分层核对 | FULL持久化承诺还依赖DB复制/备份；不在未知拓扑下承诺RPO=0 |

默认采用滚动30天作为讨论窗口，数值目标由业务负责人确认后冻结。测试运行单必须在开始前填写`受理/首事件/完成/恢复/Stop`预算；没有目标值只能报告测量结果，不能签署上线通过。

<a id="overview--33-容量验证方式"></a>
#### 3.3 容量验证方式

不能从租户200许可、下游64许可或Hikari10连接直接推算可承载用户数。先固定请求结构，再逐级加压得到安全承载点；同时测正常、故障降级、恢复及少一实例时的容量。

- 连接需求估算：`在途流数 × 每流事件速率 ÷ 每批事件数 × 每批持连接时间 + 其他业务占用`；模型用于选择压测区间，不作为性能承诺。
- 内存预算：JVM基础占用 + 活跃Run累计数据 + 各缓冲区/对象副本 + 连接发送数据 + 文件在途字节 + GC余量；还要给direct/native及进程额外占用留预算。
- Admin/Tool/Relay/Chat四服务所有实例数据库池、扩容及滚动发布重叠副本、治理保留和其他连接之和不得超过DB安全预算；隔离线程池或Redis命名空间不等于隔离共享资源。暂不全面读写分离，状态判断和Resume保持读取权威主库。
- 限额降低须验证忙响应及客户端退避；重试、重连、回源和Watchdog同时恢复时也必须受预算约束。

### 4. 执行阶段、接口与交接

| 阶段 | 输出 | 出口门槛 |
|---|---|---|
| A 基线 | 本轮文档、场景/接口覆盖、环境表、目标口径 | 未知项有责任角色和关闭阶段；不能以默认配置代替生产实值 |
| B 优先加固 | W01–W06及适用的信任边界整改 | 资源耗尽和关键数据/隔离风险通过关联测试；无静默丢结果 |
| C 一致性、旁路与部署 | W07–W14，指标、运行控制、共享资源、静态源与区域接管 | 混合负载下主流程与治理资源可用；区域单写屏障可证；协议变更完成联调 |
| D 验证演练 | T01–T35、D01–D12结果与证据 | 确定性测试、真实依赖、多实例、AZ及Region故障和恢复分别有证据，不相互替代 |
| E 发布交接 | 配置清单、回滚工单、值班运行册、风险接受单 | SLO已冻结，适用高风险关闭或阻断相关功能，上线责任人签署 |

工作包可按依赖并行，阶段B不是对尚未验证协议的提前上线许可。后续代码变更按小批次执行：新增可观测性/保护→隔离环境测试→少量实例灰度→观察业务、资源和恢复指标→逐批扩大。回滚同时核对在途任务、旧版本协议和DB兼容性，不能只替换镜像。

本轮对外接口不变。后续新增限制优先采用配置；每个参数明确单位、作用域、拒绝语义和是否需重启。引入幂等键、恢复分页协议、错误码或Relay代次字段时独立评审，同步OpenAPI和前端测试；不能在运维文档中假定已可调用。

责任按应用、测试、DBA、SRE/网关、前端、下游和业务负责人分配；项目启动时把角色映射到实际人员。每周按风险编号更新状态`OPEN→IMPLEMENTING→VERIFIED→CLOSED`，环境证据缺失标`ENV`，接受风险标`ACCEPTED`且填写审批人、适用范围和到期日。本轮未实施修复，不能直接标CLOSED。

风险接受单固定记录：风险ID、触发条件与影响、临时限制、观测和预案、业务接受人、到期日、永久措施和复审时间。高风险若无合格证据或接受单，阻断相关功能上线；不能用“已写方案”关闭风险。

### 5. 最终验收清单
