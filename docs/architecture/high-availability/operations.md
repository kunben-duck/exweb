### 共同处置顺序

事件指挥（IC，由应用负责人或当值SRE担任）统一记录 `t_detect/t_contain/t_fault_removed/t_service_recovered/t_backlog_reconciled`，其中移除故障不等于恢复。应用负责人检查业务状态，DBA检查连接/锁/索引，SRE负责路由/实例/资源，下游负责人查真实副作用，前端负责人查恢复游标，测试人员记录证据；安全/存储负责人参与RB10。

先核对影响面与正在进行的发布，再限制导致放大的入口，同时保留**当前合法写Region**的Stop、内部回调和必要状态读取路径。Region切换时旧Region的回调、后台写和外呼也必须受隔离，不能以保留控制链路为由绕过单写屏障。不能一刀切阻断所有接口后把HTTP错误率下降记为恢复。任何对外通知由事件指挥通过既有渠道执行，本文件不自动发送消息。

可用的只读诊断示例（在对应运行宿主、具备JDK工具且值班权限允许时；`HA_PID`和目录必须由执行单明确提供）：

```sh
: "${HA_PID:?填写已确认的Java进程PID}"
: "${HA_EVIDENCE_DIR:?填写本次演练证据目录}"
mkdir -p "$HA_EVIDENCE_DIR"
jcmd "$HA_PID" VM.version > "$HA_EVIDENCE_DIR/jvm-version.txt"
jcmd "$HA_PID" Thread.print -l > "$HA_EVIDENCE_DIR/threads.txt"
```

该片段不是故障注入。本机dump可能包含业务线程名/上下文，依证据权限管理。JFR、heap dump、NMT需先确认资源和启用条件；内存/磁盘濒临上限时不临时执行大heap dump，不用持续全量线程dump增加故障负担。

## 2. 十四类故障运行册

<a id="rb01"></a>
### RB01 — 堆、native memory与频繁GC

**关联：** R01/R03/R09/R12，T01/T03/T09/T12/T26，D01/D05/D06。

1. **触发与影响确认**：heap/RSS/direct memory或线程/FD达到执行单停止线，GC时间增加、首事件退化、进程被OOM终止。对照请求量、历史补读量、入站帧、上传/下载、Redis入站与平台线程数，区分堆对象、direct buffer和线程栈；确认是否单实例、租户或全实例。
2. **止血**：通过已验证网关规则先限制恢复、文档和高频新Run来源；观察流和控制接口保留。若单实例继续增长，先摘流，记录该实例持有的Run/lease，截取一次低成本诊断后按预案替换实例；一次只操作一个实例并检查剩余容量。
3. **禁止动作**：不持续扩大Xmx/队列、无限重试、全实例一起重启或删除Redis事实替代物；不用客户端断开代替Stop；未提交结果不能因本地进程消失而声称完成。
4. **恢复步骤**：确认依赖恢复/输入速率下降后，小批恢复新流量；有界队列及字节上限未修复时保持入口限制，记录受影响功能；必要的限额配置通过已测配置发布，不假设热更新。
5. **数据核对**：按摘流前清单逐个检查Run、Execution、Interaction、异步任务，FULL补读验证最后seq；no-store记录不可恢复结果。确认下游仍执行的任务和文档孤儿对象。
6. **退出与升级**：资源在观察窗口内回落且无持续增长，Stop/首事件和治理满足签认目标，遗留任务全部有结论。应用负责人主责，平台SRE处理宿主OOM，DBA/下游负责人处理恢复阻塞；无法解释增长转RB02和资源专项profile。

<a id="rb02"></a>
### RB02 — CPU高位、序列化与GC负担

**关联：** R01/R09/R11/R16/R25/R26，T11/T16/T25/T26，D01/D08。

1. **触发与影响确认**：CPU/容器节流持续超过停止线且长尾恶化。以CPU采样、分配率、GC、线程状态判断JSON解析/复制、脱敏/日志、重试、锁竞争或宿主限额；CPU繁忙本身不是死循环证据。
2. **止血**：限制被证据指向的大帧/高频事件、历史搜索/树查询或恢复来源；若是下游5xx诱发重试，联动RB05减少新逻辑请求。配置开关能隔离的标题/记忆等旁路按发布预案关闭，已在途任务继续跟踪。
3. **禁止动作**：不增加线程数掩盖CPU瓶颈，不全量记录大payload，不连续heap dump或强制GC，不在无profile时全局关闭校验/日志。
4. **恢复步骤**：确认热点消退后分档放量，每档观察CPU节流、GC、首事件、completed Run数量和积压；一旦热点重现，退回上一档并保留输入形状用于T26。
5. **数据核对**：检查因超时/取消导致的未终态任务、重试副作用与seq缺口，防止“CPU恢复但任务重复/丢失”。
6. **退出与升级**：资源及主链路恢复且无队列持续增长；应用性能负责人主责，平台确认CPU quota/宿主竞争，前端/下游共同定位重连或重试放大源。

<a id="rb03"></a>
### RB03 — 数据库慢、锁等待、连接耗尽或切换

**关联：** R02/R07/R10/R11/R13/R15/R23/R25，T02/T07/T10/T11/T13/T15/T23/T25，D02/D07/D08。

1. **触发与影响确认**：Hikari pending/acquire timeout、事务年龄、锁等待上升，heartbeat失败或lease余量不足。DBA区分不可连接、慢SQL、锁持有、连接总量和主备切换，并核对最近DDL/配置。
2. **止血**：先收紧恢复/搜索/树/批删/旁路入口和新Run，保留控制链路预算；暂停非必要批处理。定位阻塞会话后由DBA仅终止明确的异常/演练事务，保存事务与SQL指纹；共享实例连接池耗尽时摘流故障实例，不能假定应用有独立治理连接池。
3. **禁止动作**：不无限加连接池、不关闭唯一约束/fencing、不把搜索错误转换为空列表、不直接UPDATE Run终态、不可在事故中无计划重建所有索引。客户端timeout不证明事务已回滚。
4. **恢复步骤**：DB连接恢复后先跑状态/控制请求，再少量新Run；确认旧SQL结束、锁释放、Watchdog能完成下一轮再放辅助流量。切换后检查驱动连接更新与失败事务，不能只验证新连接成功。
5. **数据核对**：核对未知提交请求、CANCELLING/孤儿execution、批删all-or-nothing、分享/上传登记，逐项判断已提交/未提交/未知；索引完整性与有效状态单独检查。
6. **退出与升级**：池等待回落、治理持续推进、签认窗口内无残留锁/无界积压且正确性对账完成；DBA主责，应用负责人处理事务边界，SRE处理网络/主备切换。未恢复治理转RB09，不以DB健康绿灯关闭事故。

<a id="rb04"></a>
### RB04 — Redis不可用、订阅中断或实时广播积压

**关联：** R04/R07/R09/R16，T04/T07/T09/T16，D03。

1. **触发与影响确认**：Redis超时/重连、广播lag、RECOVER_REQUIRED突增，前端无新帧但DB已有新事件。区分缓存、取消标记、恢复锁优化与Pub/Sub问题；确认FULL和no-store受影响用户范围。
2. **止血**：限制前端紧循环重连和HTTP补读，网关使用已验证恢复限额；保留DB余量。实时故障明确反馈用户，FULL按状态+游标补读，no-store保持“可能无法补回”的语义。缓存miss风暴时限相关入口，不能为命中率清空全缓存。
3. **禁止动作**：不把Redis当事实源重建终态；不把`local-only`或粘性路由当跨实例无损保证；不把`merge`当自动安全降级；不让所有客户端立即afterSeq=0。
4. **恢复步骤**：SRE验证目标Cluster连通、拓扑/订阅重建，先恢复少量topic观察消息顺序，再逐步恢复补读；应用对缓存值重新核验DB状态。listener线程异常时按RB01处置。
5. **数据核对**：FULL比对已提交/广播/消费seq和最终状态；no-store单独统计业务结果缺口；检查暂停期间旧取消标记/恢复锁是否影响状态，禁止批量删除不明key。
6. **退出与升级**：实时lag和恢复量回落、FULL缺口补齐、no-store缺口已记录、DB回源压力正常；平台Redis负责人主责，应用/前端负责恢复，下游仅处理被错误重复执行的任务。

<a id="rb05"></a>
### RB05 — Relay、DomainAgent、Intent或鉴权异常

**关联：** R05/R06/R16/R25，T05/T06/T16/T25，D04。

1. **触发与影响确认**：connect/first/idle/total timeout、401/429/5xx、鉴权等待或Stop未知结果上升。按provider、逻辑请求和attempt拆解，确认故障是在token、网络、远端处理还是本地阻塞资源。
2. **止血**：网关先限制受影响请求入口/用户范围，降低新逻辑调用；只在已经验证的路由合同允许时切换provider或关闭可选信号。对session级迟到Stop仍可能存在的会话，暂停该会话新续接并与Relay核对命令，不静默新建session改变用户语义。
3. **禁止动作**：不跨provider盲目重放已产生副作用任务，不扩大重试次数，不绕过鉴权；WeLink等未知发送走RB09。关闭Relay Bean是配置发布而不是当前请求熔断开关。
4. **恢复步骤**：用测试账号验证鉴权、一次查询及Stop，确认token底层线程释放；由下游明确未决任务与Stop代次/顺序后恢复会话续接，再逐档放量。
5. **数据核对**：关联本地Run与远端runtime session/task、旧Stop/新Run、异步回调；记录失败、取消、未知三种事实，不能把本地cancelled解释成远端一定停止。
6. **退出与升级**：依赖稳定、放大比受控、底层资源归还且未知命令已对账；应用与下游负责人共同关闭，鉴权负责人负责token问题，Relay代次证据缺失时保留上线阻断。

### RB06 — 恢复风暴、慢客户端及多页签

**关联：** R03/R20，T03/T20/T27，D05/D07。

1. **触发与影响确认**：Resume并发/查询行数、连接创建、RECOVER_REQUIRED、重复subscribe和WS发送超时同时增长；识别长历史用户、多个标签页、网关idle截断或客户端错误游标。
2. **止血**：网关限制HTTP Resume及WS握手/订阅的来源频率，前端部署已有可用的退避抖动策略；无前端策略时优先入口限流与用户可见等待，不能声称服务器已具备独立HTTP恢复配额。保留Stop及正常聊天预算。
3. **禁止动作**：不要求所有用户清游标，不重发NEXT代替重连，不把HTTP200的ACCESS_DENIED当成功，不任意放大live buffer。
4. **恢复步骤**：优先恢复少量客户端；按服务端建议游标重新订阅并按事件身份去重，再分批恢复其余；确认网关idle/总期限与流式协议匹配，清理已关闭连接注册。
5. **数据核对**：每Run核对已消费最大seq与真实缺口，不能只比较最大数字；FULL补回缺失，no-store明确缺口，已读水位仅在实际消费后推进。
6. **退出与升级**：恢复流量降到基线、无持续缺口/重连循环，主链路稳定；前端和应用主责，SRE调整验证过的网关限制。生产前端必须单独验收，联调样例不能替代。

### RB07 — 存储异常、慢文件流、临时磁盘满及孤儿对象

**关联：** R12/R21/R22，T12/T21/T22，D06。

1. **触发与影响确认**：上传/下载超时、FD/存储连接增长、临时磁盘不足、对象与DB记录差异。先确认实际provider，API Store整文件数组与OBS流式路径分别定位。
2. **止血**：入口限制新上传/下载并保留元数据/状态查询；慢客户端导致的在途流由已验证连接关闭机制逐步清理。磁盘满时只清理明确失效的测试/临时文件，先确认没有在途引用；真实事故按存储清理策略执行，不能泛删临时目录。
3. **禁止动作**：不把文档软删除当物理对象已删除；不在未知上传结果时盲重传；不清bucket/对象前缀外文件；不切本地磁盘当多实例持久存储。

5. **数据核对**：按操作标识、对象key、checksum、上传时间和文档记录核对，先确认没有有效引用再清孤儿；当前缺持久操作ID/自动对账时以限定前缀清单由存储与应用共同处理，不假称有一键补偿接口。
6. **退出与升级**：FD/连接/磁盘恢复、流关闭可验证、孤儿对象和未知上传全部有结论；存储/SRE主责，应用处理生命周期，信任/TLS问题转RB10。

5. **数据核对**：列出发布窗口内Run、WAIT/RESPONDING/async与已删除active，检查每个都有明确终态/等待语义；核对兼容DTO、恢复游标和旧客户端错误行为。
6. **退出与升级**：所有副本版本明确、实例摘流验证通过、观察窗口内不再重启放大、遗留任务对账完成；发布负责人/SRE主责，DBA、应用和前端共同签认。

6. **退出与升级**：没有未解释的重复/悬挂/权限绕过，UNKNOWN已明确业务处置；应用负责人主责，DBA、前端和下游共同对账，涉及用户可见错误由业务负责人确认补偿措施。

### RB10 — 文档信任边界与存储TLS

**关联：** R21/R22，T21/T22，D06。

1. **触发与影响确认**：可信provider引用被客户端metadata改变、附件指向异常目标、OBS接收错误证书或hostname。区分已确认错误行为和未证实的越权/泄露，保存限定范围证据。
2. **止血**：入口暂阻断受影响metadata编辑/附件使用/存储路径，保留必要状态读取；隔离异常endpoint，按实际证据协调凭据处置。当前没有白名单或严格TLS现成开关，不写“打开开关即可恢复”。
3. **禁止动作**：不以关闭证书校验恢复可用性，不允许客户端指定truststore/可信URL，不用生产文件验证可疑端点，不在不明归属的metadata上批量覆盖providerDocument。

6. **退出与升级**：错误引用无法影响可信附件、错误证书被实际SDK拒绝、合法路径成功，影响范围和修复记录完整；安全负责人、存储负责人及应用负责人共同关闭。

### RB11 — 四服务共享数据服务与Admin/Tool依赖链

**关联：** R28/R29/R30，T28/T29/T30，W11 / D09；图[DEP01](deployment.md#dep01)、[DEP02](deployment.md#dep02)。主责为四服务负责人，DBA/缓存与DomainAgent负责人联合处置。

1. **触发与影响确认**：四服务错误同时上升、DB池/锁等待、Redis热点/淘汰、Admin映射版本不一致或Tool执行结果UNKNOWN。按服务及其全部副本汇总资源，明确故障来源与被连带服务；查询映射版本和执行链路，不把所有超时归为Chat故障。
2. **止血**：通过已验证的服务级入口/作业控制限制产生压力的来源，暂停非必要导出、批处理和高成本恢复；保留当前主Region治理预算。Admin不可用时只允许已明确有效期和撤销规则的可信缓存范围续服，无法确认映射的新调用有界拒绝；Tool未知执行停止自动重试。
3. **禁止动作**：不统一扩大四服务连接池、不清空共享Redis、不把Chat“Redis非事实源”推及其他服务；不临时改skillId指向规避故障，不将Tool超时当DomainAgent未执行。
4. **恢复步骤**：DBA/缓存负责人先恢复数据能力，确认连接/锁/订阅及复制；随后核验Admin可信映射和Tool查询，确认Relay/Chat控制路径，最后分档恢复新业务和旁路负载。Redis持久状态用途未查清时停止“重建为空”的恢复动作。
5. **数据核对**：按一次逻辑请求关联Admin映射版本、Tool执行ID、DomainAgent真实回执及Chat/Relay事实；比对四服务提交标记和Redis独立持久状态，UNKNOWN由下游确认后处理，不盲重跑。跨Region问题转RB14，不能从本运行册直接提升备用库。
6. **退出与升级**：四服务资源与业务均稳定、缓存回源峰值受控、映射一致和未知任务有明确处置，才算恢复；单个Chat探针恢复不足以关闭。数据库/缓存负责人解决共享层，Admin/Tool及下游对执行与映射共同签认。

### RB12 — WCM静态源、ALB文根及GSLB入口异常

**关联：** R31/R32，T31/T32，W12 / D10；图[DEP04](deployment.md#dep04)、[DEP03](deployment.md#dep03)。主责为WCM/前端和入口平台负责人。

6. **退出与升级**：新旧浏览器完整链路、四服务路由正负例和长连接恢复通过，静态/入口恢复时间满足目标，才受控回切静态主源；不自动来回切换。WCM负责人确认源站，前端确认资源兼容，ALB/GSLB负责人确认路由/解析，业务写权由IC/DBA按RB14确认。

### RB14 — Region单写接管、分区隔离与受控回切

**关联：** R35，T35，W14 / D12；图[DEP05接管](deployment.md#dep05)、[DEP06回切](deployment.md#dep06)。IC统一指挥，DBA、ADS/入口、四服务和下游负责人共同签认阶段门槛。

1. **触发与影响确认**：主Region运行面/入口不可恢复或区域分区；核对A是否仍有存活实例、DB写端、定时任务、外部调用和旧连接。区分“探测不到A”和“A已被可靠隔离”；备用B的复制位置、映射/对象/静态版本、容量和依赖连通均纳入接管清单。
2. **止血与单写门槛**：限制新写并记录在途及UNKNOWN；执行DEP05-03/04，取得旧四服务后台/外呼和旧数据库写端的独立隔离证明。证明缺失即执行DEP05-14：B保持禁写，不因RTO压力越过。GSLB切换、旧实例暂不响应、Chat本地fencing均不能替代该证明。
3. **禁止动作**：不自动提升双主、不自动回切、不重跑未知Tool/Relay/DomainAgent任务；不将异步复制称为RPO=0，不为no-store新增正文持久化；不在提升后简单拨回DNS，不将隔离屏障设为120秒自动过期。
4. **接管步骤**：隔离证据通过后，按DEP05-05/06确认B数据库及业务附件对象恢复点、允许损失及缺口；对象版本/内容、DB文档引用与租户/访问权限必须核对，不能只验证静态发布包。超批准RPO或无法核对时阻断相应接管放行。DBA提升B后检查四服务数据端点/映射、Redis、后台与外呼主权；受控探针通过才开放符合条件的B业务，最后改GSLB/DNS。每阶段超时暂停扩流并保持安全单写。
5. **数据核对与用户结果**：比较旧主已提交标记和目标实际恢复集，分别列DB事实、Admin映射、业务附件对象/DB引用/权限及外部副作用差异；DB引用已到而对象未到必须列明，批准的对象损失也要隔离受影响附件上传/下载/引用功能，只能报告限定范围恢复，不能报全功能恢复。FULL只恢复有效点内历史。Runtime不可靠接管，UNKNOWN由远端查询/对账，不自动重跑；记录页面、入口、业务及遗留任务恢复时间。
6. **受控回切**：A修复后维持隔离并预先追平；DEP06-05只能预收集水位，QUIESCING时仍可能有迟到callback/终态提交。DEP06-06强制隔离B数据写入及外呼后，DEP06-07必须取得或证明**隔离后的最终提交位点**并让A追平校验，同时通过业务附件对象恢复点、DB引用/权限核对，才可DEP06-08激活A。提前追平不替代最终检查。失败执行DEP06-13：B未失权继续B；B已隔离/A未激活先证明无人写再恢复B；A已激活必须重新转移主权才能恢复B，不一概拨回。
7. **退出与升级**：唯一主Region证据明确、旧域重连/旧DNS/迟到消息均不能写或触发旧副作用，实际RPO及损失集完成签认，UNKNOWN有处置，跨域复制与热备能力已按新主重建。IC、DBA、四服务和下游共同关闭；任何双写迹象立即停止新增业务写并由IC选择可证明安全的单写端，不能靠平均指标宣布恢复。

## 3. 演练通用执行协议

以下为12组演练的固定执行步骤；同一编号包含多个子场景时，**每个子场景恢复到已确认的安全状态后再开始下一个**。D12已经转移写权时不能用“复位”自动切回旧主，只能另走受控回切。完成单故障验收后，才允许在相同影响范围内追加已列明的叠加步骤。不得借“演练方案”扩大到新环境、新租户或新依赖。

- **范围**：D01–D08通常一次影响隔离环境一个实例或一条依赖链路；DB/Redis切换由管理员单独操作。D07/T27通用故障域检查可由D11跨AZ记录承接；D09共享依赖、D10入口、D11 ADS/AZ、D12 Region是明确扩展范围，必须逐项列四服务/平台资源ID及独立管理观察通道，不能临场扩大。
- **时长**：5分钟稳态基线；常规故障注入60秒，部分用例30秒/15秒依正文；可撤故障规则上限120秒，撤销后至少10分钟观察并完成对账。平台/数据切换按管理员确认的分阶段期限执行。D12主权隔离屏障不属于故障规则，不随TTL撤销；提升后的超时处理为保持安全单写并停止扩流，不是自动逆向提升或回拨DNS。
- **自动停止**：触及任一资源安全线、观察流控制/恢复超签认期限、出现重复终态/双写/越界或失去目标监控，立刻停生成器和扩流、撤销可撤故障；故障规则TTL独立于被测进程。Region写权保护屏障继续保持，由IC/DBA独立决定后续，故障网络恢复也不能让旧主自动获得写权。执行人与观察人不能是同一个自动化任务。
- **双重撤销**：注入前在空载目标验证“创建故障规则→查询范围→撤销→健康检查”，失败不开始；观察人持有独立撤销操作。D12另验证“故障规则撤销/旧域重连后主权屏障仍生效”，不能把解除故障和解除保护合并在finally中。
- **观察负载**：另租户每10秒普通Run、每30秒Stop，加一个quiet WS和状态查询；内部回调按用例发送。D09–D12增加Admin可信映射读取、Tool可对账测试任务、Relay和四服务状态探针；只有当前合法主Region可执行测试写入/外呼，备Region只做不会产生业务副作用的准备验证。
- **恢复阶梯**：撤销故障后先停止重试/恢复突发，维持观察流；确认治理推进后依次恢复测试目标负载的25%、50%、100%，每档观察2分钟，失败退回上一档。百分比以本次已测安全负载为基数，不代表生产容量。
- **证据**：统一保存时间线、故障规则命中/删除、配置与artifact、状态对账、资源峰值和结束值；开始/结束/异常终止都记录。D编号关联所有实际执行T编号，未执行的子场景不得随整次演练填PASS。

## 4. 十二组演练执行单

### D01 — 慢消费、高频事件与CPU/native memory

**目标/关联：** T01/T09/T26，RB01/RB02/RB04。应用负责人执行，SRE观察，测试负责事件与状态核对。

1. 预置具有限流开关的测试Relay/DomainAgent以及有TTL的事件存储/handler屏障；确认测试实例A JVM配额、独立采样和B观察流。任一屏障不具自动释放则本子场景BLOCKED。
2. 子场景A：按T01帧速率阶梯，先延迟落库200 ms，后阻塞30秒；观察累计队列、正文和GC，命中停止线即停止，不等待真实OOM。
3. 复位后子场景B：只延迟Redis入站handler 100 ms，风暴60秒，观察平台线程及拒绝；发布端和接收端指标分别采集。
4. 复位后子场景C：按T26深度/大小/频率输入，采样CPU和分配30秒；有证据才归因到JSON、复制、GC或忙循环。4小时稳态作为后续容量用例，不延长本次故障注入TTL。
5. 按恢复阶梯放量，逐个检查Run终态及socket/timer/线程/FD释放；保存首次触界档位和未修复限制。成功必须同时满足资源上界、控制流可用和业务正确性。

**撤销/回滚：** 停止测试publisher/agent输出，解除测试屏障，撤销代理规则；若A失稳，摘流并恢复相同基线实例，再按租约对账。未经验证不把重启本身当治愈。

<a id="d02"></a>
### D02 — 数据库连接、锁与治理竞争

**目标/关联：** T02/T07/T13/T23，RB03。DBA负责锁及连接，应用负责事务时序，SRE独立观察。

1. 建立专用测试数据和DB管理会话，设置数据库侧自动事务回滚/会话期限并验证管理员独立终止能力；记录锁定行的测试Session ID和事务ID，禁止无谓锁全表。
2. 子场景A：持一个测试Session行锁60秒，并发标准准入、批删与状态观察；反向批次按T23执行，记录锁序和all-or-nothing。
3. 复位后子场景B：按T02逐步保留测试连接，直到预设治理余量边界，检查Stop/heartbeat。不得占满所有管理连接；安全线到达立即回滚保留事务。
4. 复位后子场景C：按T13锁待claim记录，观察当前scan结束及下一轮是否启动；最后单独加入Redis慢30秒，验证T07哪些缓存操作仍在事务内。
5. 解除所有锁/延迟，先确认旧SQL已结束，再恢复流量；核对所有删除、Run、孤儿execution、Interaction与callback结果。

**撤销/回滚：** DBA回滚明确测试事务，必要时仅终止已登记的测试会话；撤销Redis延迟；记录未决事务，不能通过直接改状态掩盖。真实openGauss切主另由DBA提供专用切换/回切执行单，开发库模拟不替代它。

<a id="d03"></a>
### D03 — Redis网络中断、广播缺口与Cluster恢复

**目标/关联：** T04/T07/T09，RB04/RB06。Redis/SRE负责链路与拓扑，应用和前端负责交付核对。

1. 两实例分别承载执行与订阅，准备FULL与no-store各一组任务；记录源事件清单和已消费游标，确认代理只影响A到测试Redis的指定链路。
2. 子场景A：丢弃该链路60秒，保持DB可用；观察事务/回源、发布队列和用户可见停顿。再恢复链路，按建议游标分批补读。
3. 复位后子场景B：终态commit后publish前停止A，B继续读状态/补历史，核对FULL与no-store差异，采用T04屏障证明注入点。
4. 复位后由Redis管理员在专用Cluster执行一次已验证的切主与订阅重建；记录重定向、拓扑刷新、短时重复/乱序。没有真实Cluster则此子项BLOCKED。
5. 检查广播、消费和DB清单：FULL最终无缺口，no-store缺口单列且未违反留存；避免全量恢复风暴压垮DB。

**撤销/回滚：** 删除网络规则并验证所有指定通路；管理员按专用执行单恢复Cluster健康，恢复A副本；不运行FLUSHALL、不清所有取消key，不自动切`local-only`。

<a id="d04"></a>
### D04 — 下游黑洞、鉴权阻塞与迟到Stop

**目标/关联：** T05/T06/T16，RB05。下游/鉴权负责人操作测试钩子，应用核对本地状态，SRE观察资源。

1. 准备可独立恢复的token resolver、HTTP故障端点和真实测试Relay；对每个依赖单独映射调用目标，先用低并发验证30/60秒延迟可自动撤销。
2. 子场景A：token阻塞60秒，再依次401/429/503及首帧后断流；记录逻辑请求到所有底层任务结束的总时间与attempt次数，确认观察流不被共享鉴权线程阻塞。
3. 复位后子场景B：T16同key cache miss与cache关闭留存路径；确认线程切换和重复请求实际行为，不靠推断下结论。
4. 复位后子场景C：A收到本地cancelled后B续接同runtimeSession；延迟A session级Stop15秒，分别在B首帧前后放行，联合Relay命令日志证明代次安全；Intent动态专家、固定专家、聚合应用子专家来源分别完成该场景。
5. 资源恢复后逐个对账远端task/session及本地Run。只能证明本地cancelled但无法证明B未被误停时，R05保持未关闭。

**撤销/回滚：** 释放resolver、恢复端点正常响应、取消延迟队列；由下游清理专用会话和未决命令，再恢复新续接。禁止以换session或丢弃迟到命令掩盖实际协议风险。

<a id="d05"></a>
### D05 — 恢复风暴、跨实例退出与取消收口

**目标/关联：** T03/T04/T13/T14/T17/T20，RB06/RB09。SRE控制实例，前端负责重连，应用负责状态对账。

1. 两实例，长历史FULL和no-store、一个quiet运行任务、一个等待交互和一个async任务；准备T03历史规模与多页签生成器。启动前验证B能接管观察流且不会与A共用instance-id。
2. 子场景A：断开测试客户端30秒后分批重连，同时注入建议游标小于本地最大seq；校验缺口和HTTP200业务错误处理。
3. 复位后子场景B：A执行quiet Run，B提交CANCELLING后退出，A继续续lease；观察既有Watchdog是否能收口，再验证后续加固行为，不能以等待lease过期替代这个场景。
4. 复位后子场景C：kill执行实例、异步回调commit后kill及删除commit后丢Stop分别进行；每次只终止一个实例，重启恢复副本并核对旧owner后续写入被拒绝。依T04/T13/T14补充矩阵执行早到、重复、过期、并发callback及Interaction claim孤儿，分别保留结果。
5. 对所有测试Run/Interaction/async与deleted Session逐项登记最终状态；已删除会话新恢复入口应符合统一访问政策；资源和恢复并发回到基线后结束。

**撤销/回滚：** 恢复客户端链路，关掉突发生成器并按抖动重连；恢复实例数/基线包，撤销屏障；无期限自动收口的任务列为缺陷并通过正式Stop/联合下游处置，不直接改库清表。

<a id="d06"></a>
### D06 — 文件生命周期、可信metadata与TLS

**目标/关联：** T12/T21/T22，RB07/RB10。存储/SRE负责资源与证书，安全与应用共同审查引用。

1. 使用独立bucket前缀、临时卷、测试endpoint和测试凭据；列出创建对象的清理清单。代理/TLS终结点不能连接真实存储，错误URL只指向隔离接收器。
2. 子场景A：按T12大文件阶梯，分别慢下载30秒、客户端取消、上传后DB失败；磁盘不足仅填充专用卷至预设安全线，不填宿主根卷。
3. 复位后子场景B：PATCH可信metadata并发起附件Run，捕获最终docList，确认不把用户字段当服务器引用；合法重命名同时回归。
4. 复位后子场景C：实际OBS客户端分别访问有效、未受信、错误hostname、过期证书端点；每种最多120秒。当前未修复实现接受错误证书时记录FAIL，不继续扩大测试数据。
5. 按对象key/checksum/文档ID对账，确认流、FD、permit与临时文件均释放，验证所有错误证书场景被修复版本拒绝。

**撤销/回滚：** 恢复证书/代理，停止慢客户端，删除专用卷填充物及确认无引用的测试对象，撤销测试凭据和truststore。生产凭据轮换属于事故证据判断后的安全响应，不作为该隔离演练默认副作用。

<a id="d07"></a>
### D07 — 探针、索引、滚动发布及回滚

**目标/关联：** T15/T27，RB08/RB03。发布负责人指挥，SRE执行摘流，DBA核对迁移。

1. 先记录真实探针、路由、graceful期限、网关idle及回滚包；核查新旧版本和数据库兼容。在独立DB副本完成索引脚本重复/中断/有效性验证，不能在发布演练中随意删一致性约束。
2. 子场景A：只阻断A的DB60秒，比较默认health与实际请求/治理，检验readiness摘流和liveness是否引起错误重启；实际策略缺失时记录缺口，不能临时宣称已满足。
3. 复位后子场景B：网关摘流A并确认无新Run到A，处理在途Run和WS，再正常停止A；启动新版本后只给少量流量，跑受理/首事件/Stop/callback/Resume。
4. 复位后子场景C：按同样负载直接异常退出A，与正常退出比较；确认lease、fencing和后台任务恢复。模拟一项可控灰度失败，暂停放量并回滚已验证的兼容包/配置。
5. 记录每一阶段请求实际实例、Run年龄、恢复峰值及旧客户端兼容，达到退出条件后才恢复全负载；没有业务健康readiness/后台drain不能用HTTP graceful成功代替。
6. 完全复位后执行T27备份恢复子项：DBA只对专用源库备份，恢复到全新隔离目标；核对备份截点前/附近/后的已知已提交标记，检查约束、索引和应用读取，记录真实RTO/RPO。执行单指定恢复任务最大时长和停止命令，超时仅停止隔离目标任务，不覆盖或回切源库。
7. 完全复位后，只有已验证多个故障域及撤销路径时，平台停用一个测试故障域的明确实例集合60秒，检验剩余副本承载、控制链路与恢复；绝对上限120秒自动回接。无真实拓扑/足够容量/域级恢复工具时该子项BLOCKED，不用单实例重启替代。
8. 在独立灰度实例执行无效配置启动、测试凭据轮换和T22证书正负例；日志/临时磁盘告警只用T12专用卷触发，确认告警能定位且恢复后消除。每类单独复位，凭据按现有已验证轮换协议操作，无对应机制时保留缺口。

**撤销/回滚：** 撤销网络规则、恢复路由/故障域及副本数，按兼容证据回滚应用配置；DBA独立处理DDL状态，禁止把jar回滚当DDL自动回退。备份恢复完成后保留日志/标记差集并销毁隔离目标；恢复轮换实验配置、撤销测试凭据、清理专用卷。未完成迁移/数据对账保留发布阻断。

<a id="d08"></a>
### D08 — 状态竞态、外部副作用与旁路争抢

**目标/关联：** T08/T10/T11/T18/T19/T24/T25，RB09/RB03/RB02。应用/测试负责屏障和断言，下游核对副作用，DBA观察锁。

1. 准备专用WeLink收件人、可丢响应的代理、可释放的复制/分享/路径事务屏障；每个测试逻辑请求有独立追踪摘要。T24按本轮保守合同执行：运行中只浏览历史，active path切换必须Session锁后确认无活动Run；远端无对账能力时外部副作用子场景BLOCKED。
2. 子场景A：按T08提交后丢响应，先查事实再决定重试；按T18交错分享与删除、逐点中断分支复制；按T24运行path与NEXT/终态/删除竞争。每个屏障30秒上限，全部复位后再下一组。
3. 复位后子场景B：WeLink收到消息但响应丢失，另测发送成功、本地记录失败；统计远端实际数量，未支持幂等时演练“停止重试→查询/人工对账→记录UNKNOWN”的处置。
4. 复位后子场景C：旧偏好worker、长历史查询和标题候选分别阻塞30秒；在独立通过后叠加三类短突发60秒，观察主Run首事件、Stop和heartbeat，核对标题人工修改不会被旧结果覆盖。
5. 对每个逻辑请求列实体数、终态数、分享资格、leaf、投递数量和旁路提交结果；所有未知和部分写入必须有明确后续处置，不能只以HTTP恢复收尾。

**撤销/回滚：** 释放所有屏障/worker，恢复响应，停止旁路突发；通过既有接口清理测试会话/分享并核对收件箱，已发送内容不声称已召回；配置实验通过发布恢复原值。

**目标/追踪：** R28–R30 / T28–T30 / W11 / RB11；[DEP01](deployment.md#dep01)、[DEP02](deployment.md#dep02)。四服务负责人参与，DBA/缓存负责数据层注入，Tool/DomainAgent负责人负责真实执行对账，测试独立观察。初始NOT_RUN。

5. 按数据服务→可信映射/查询→控制路径→新业务→旁路的顺序恢复，负载25%/50%/100%各观察2分钟；四服务逐个核对提交、映射、运行及副作用，收集总连接与回源峰值，不能以Chat首事件恢复代替系统恢复。

### D11 — ADS运行面、控制面与跨AZ剩余能力

**目标/追踪：** R33/R34 / T33/T34 / W13 / RB13；[DEP02](deployment.md#dep02)、[DEP03](deployment.md#dep03)。ADS/SRE操作，四服务、DBA/缓存及测试独立观察。初始NOT_RUN。

1. 将四服务副本、ALB后端、宿主/容器、DB/Redis、镜像/配置/凭据和网络依赖映射到真实Region/AZ；标出独立管理通道与失去一个AZ的安全容量。虽然每Region至少两AZ，若服务实际集中单AZ或剩余资源不足，先整改布局/限额，不在未知范围直接实验。
2. 子场景A终止专用容器/宿主或隔离其运行通路60秒，验证ALB摘流、ADS实际恢复与旧owner拒写；Runtime重建后不能可靠接管的Run按确定合同收口，保留远端任务对账。
3. 完全复位后子场景B分别使测试控制面、镜像仓库、配置/测试凭据依赖不可用60秒；分开观察存量业务和发布/扩缩/重建能力。若只阻断操作客户端到控制面的网络，报告只能证明该通路失联行为，不能宣称真实ADS控制面宕机已验收。

5. 撤销故障后逐批回接原AZ，验证镜像/配置/凭据和服务身份，检查瞬间重连、租约冲突及旧Runtime副作用；回接完成不等于UNKNOWN任务自动解决。
6. ADS整个Region运行面故障超出区域内恢复目标时，只按D12启动区域接管；确认备RegionADS控制/运行能力和非ADS静态备用均不依赖故障域。原Region平台恢复后仍保持其写权隔离，直到正式回切。

**注入/停止期限：** 实例/通路规则60秒/上限120秒；AZ集合和依赖切换必须有管理员独立恢复操作。资源超线、实际影响跨出集合、独立观察失联或控制路径失效立即停止扩流并撤销故障，域级接管保护不随之解除。

**撤销与证据：** 平台恢复控制/运行资源和路由，不重建未知外部任务；保留实际容器/宿主/Region/AZ ID、平台事件、镜像digest、四服务业务与剩余容量、回接峰值和任务差集。ADS/SRE与四服务确认完整恢复边界，模拟与真实平台故障证据分开。

### D12 — 双Region写权接管、分区安全与回切

**目标/追踪：** R35 / T35 / W14 / RB14；[DEP05](deployment.md#dep05)、[DEP06](deployment.md#dep06)。IC指挥，DBA负责恢复点/数据角色，业务附件存储负责人核对对象，ADS/入口负责运行隔离/GSLB，四服务与下游负责后台/外呼/UNKNOWN核对，测试独立记录。初始NOT_RUN。

1. **建立基线与执行门槛**：固定本轮初始A主、B热备，确认四服务和第三方流向、两Region独立ALB/ADS及实际DB异步复制；B不允许业务写/外呼。预置每秒提交标记、Admin映射版本、Tool/DomainAgent回执、Relay任务、Chat FULL/no-store及对象引用，记录复制位置和丢失容忍目标。无可验证旧主隔离机制则不进行开放B写入的子场景。
2. **单写屏障预演**：空载测试验证即使A仍活着、旧DNS/长连接仍到A、定时器/回调到达，旧DB写端与四服务外呼都能被可靠阻止；验证撤销网络故障或管理工具退出不会解除屏障。若能力缺失，安全拒绝接管这项可以有证据，整体容灾放行仍BLOCKED。
3. **计划接管子场景**：按DEP05暂停新写并登记在途，执行旧应用/外呼和旧DB写端隔离，独立观察人验证后IC签认；DBA/存储负责人核对B数据库及业务附件对象恢复点、未复制提交、对象版本/内容、DB文档引用与租户/访问权限。门槛通过后才由DBA提升B；损失在批准范围且受影响功能已隔离才放行符合条件的业务。静态manifest通过不能替代业务附件核对；超批准RPO或不可核对时阻断，不因倒计时提升/放行。
4. **激活及入口**：B四服务指向同一合法数据端点，检查Admin映射、Tool副作用保护、Relay会话语义、Chat治理和Redis状态恢复；受控验证通过后仅开放B新写，再切GSLB/DNS。按25%/50%/100%恢复负载，旧入口持续验证拒写，静态页面按DEP04保持可用。Runtime中断不能靠自动重跑伪装接管成功。
5. **分区/复制滞后子场景**：完成安全状态确认后独立演练A仍存活的分区、DB复制滞后60秒，以及DB文档引用已复制而业务附件对象未复制三种情况；按相同接管顺序验证。对象缺失或权限无法核对必须阻断相关放行；批准损失仍列对象/引用差集并隔离受影响附件功能，不得报全功能恢复。网络规则最多120秒撤销但主权屏障不失效；旧主无法隔离则B禁写，记录RTO未满足与安全边界有效，不能填整体成功。
6. **旧域重连与迟到副作用**：恢复A网络而不恢复其写权，发送旧DNS请求、旧连接帧、迟到Stop/async callback及排队的Tool命令；验证无法导致旧主写入、B新Run错误取消或重复外部执行。远端结果未知保持UNKNOWN，联合下游查询/人工对账，不把缺少本地记录解释为未执行。
7. **受控回切子场景**：按DEP06修复A并预先追平；05预收集水位后，在QUIESCING阶段注入迟到callback/终态提交，证明该水位仍会变化。06强制隔离B数据写入及外呼，07取得或证明**隔离后的最终提交位点**，等待A追平并核对隔离前迟到提交已包含、隔离后写入被拒，连同业务附件对象恢复点、DB引用/权限通过后才08激活A；受控业务验证后改入口。提前追平不能替代最终检查。失败按13处置：B未失权继续B；B已隔离/A未激活先证明无人写再恢复B；A已取得写权必须重新转移才能恢复B，不自动回切。
8. **收尾**：按当前唯一主Region重建跨区复制及热备状态，记录所有服务恢复、遗留任务核对和灾备能力恢复时点；对账FULL有效恢复点内事件、no-store不可恢复结果、Admin映射/对象引用和外部副作用。确认没有未解释的重复/双写，剩余UNKNOWN与已允许损失均有负责人和处置结论，才结束。

**注入/阶段期限：** 可撤网络故障默认60秒/上限120秒；接管/回切按执行单`C_cutover/C_failback`，包含复制滞后、隔离、提升、四服务检查、DNS实际收敛及观察。时间为测试约束，实际RTO/RPO需要测量，不写成承诺；保护屏障无自动到期。

**中止/恢复：** 提升前失败可在确认仍只有A写权且数据角色未变化时恢复A入口；提升后尤其B已写入时，禁止简单回滚DNS、旧凭据或旧数据库角色，只能保持B单写或另走DEP06受控转移。双写迹象出现即停止新增业务写入与测试生成器，保留证据，由IC/DBA确认可证明安全的唯一写端；规则撤销不撤保护。

**必交证据：** 阶段签认/隔离回执、预收集水位与隔离后最终提交位点、目标追平证明、QUIESCING迟到提交及双端拒写探针、复制标记差集、业务附件对象恢复点/版本/缺失与DB引用/权限核对、批准损失及被隔离功能清单、Admin映射/静态manifest、远端执行次数/UNKNOWN、GSLB实际流向、四服务资源峰值及五种恢复时间。仅完成首页切换、DB提升或本地mock不能关闭R35；受限功能尚未恢复时不得报告全功能恢复。

## 5. 结果、复盘与上线门槛

每次演练形成一条不可被后续成功覆盖的记录：`D编号 / 子场景 / T编号 / artifact与配置 / 环境 / 执行人 / 状态 / t_detect / t_contain / t_fault_removed / t_service_recovered / t_backlog_reconciled / 失败数 / 丢失数 / 重复数 / 资源峰值 / 证据位置 / 未关闭问题`。故障发生但无法检测时记录检测缺口，不能省去发现时间。

判定成功必须同时满足：故障范围受控、自动/人工撤销有效且未撤掉主权保护、正确性断言通过、资源有界且归还、服务及遗留任务在签认目标内恢复、运行册能由另一名值班人复现。跨Region还必须唯一有效写主、实际RPO与损失集可解释、旧域恢复不自动写入、未知副作用不盲重跑。超出资源线而安全终止属于FAIL并保留证据；环境不具备或协议未确认属于BLOCKED。

复盘由相应负责人将失败项关联到风险与加固任务，注明责任人、完成条件、复测编号、到期日。整改后只重跑受影响用例与必要回归，但不能删除首次失败记录。R05、R19、R22等联合条件未验收，生产openGauss/Redis Cluster差异未覆盖，或关键SLO/恢复目标未签认时，不能以本地测试通过解除上线限制。

上线前交接必须提供真实ALB/GSLB规则、WCM与独立静态备用接入、ADS操作、四服务状态查询、监控/日志、单写隔离证明、数据恢复/回切步骤、回滚包和联系人。T28–T35的风险/加固/运行册/演练完整矩阵见[部署新增追踪矩阵](tests.md)；每项关闭须由相关服务及平台联合签认，不能只签ChatService。本文件给出操作行为及验收合同，缺失的动态开关、指标、drain、对账与平台控制能力必须先落地验证，不能由值班人员在事故中自行发明。
