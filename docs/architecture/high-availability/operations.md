# 运行稳定性故障预案与演练

源码基线：`8f48d6cc084be91bcbaad90be43dac7181636cb4`；日期：2026-09-22。本轮仅更新方案，未修改业务/部署、未执行故障注入；D01–D12全部 **NOT_RUN**，当前检查结果与待验证边界见[验证证据](evidence.md)。本页维护13类活跃运行册和12组演练，[22项测试](tests.md)给出规模/注入/断言，[风险与加固包](risks.md#risk-register)为唯一追踪矩阵。

当前ChatService、relayService、agentService共用共享DB（openGauss）和Redis；agentService管理/技能查询/统一chat/MCP/文档上传共处一个服务，intentService（第三方）独立。未来服务拆分、跨AZ/Region热备及WCM独立备用源是目标，不能当作已具备的事故切换能力。

## 1. 现场准备与共同操作

| 能力 | 已知事实与操作限制 |
|---|---|
| 入口止血 | ALB负责文根，saas gateway（SaaS统一网关）是统一网关。具体限额/摘流/鉴权规则由平台提供并预验；不虚构动态熔断或管理API |
| 新Run保护 | 本机用户速率、租户并发配置存在；`FINANCEEX_RUN_ADMISSION_ENABLED=false`会绕过保护，不是停止新准入。无通用热更新证据，限额按配置发布处理 |
| 下游/文档限额 | Runtime、DomainAgent和存储有本机并发许可；不等于集群额度，也不证明文档接收/下载完整生命周期已受保护 |
| 可选旁路 | 标题、记忆、用例库、Intent、WeLink可按既有配置发布停用；先确认业务影响，停用不保证在途任务退出，关闭Intent可能将负载转移Relay |
| 恢复与Redis | 默认实时源`redis-only`；临时切`local-only`不能保证跨实例，`merge`不证明顺序安全。HTTP Resume配额/退避、listener有界执行器属于待加固能力 |
| 治理/探针 | heartbeat/lease/Watchdog已有部分预算，完整drain、治理预留与遗留取消修复能力待验；默认health不能证明业务可用，不能停Watchdog当通用止血 |
| 共享agentService | 两条执行链共同依赖其chat/MCP，技能查询也可能是强依赖；没有模块级隔离能力时必须说明服务级摘流的连带影响 |
| 存储与500MiB | 未经T06容量验证不能扩大上限；前端经agentService授权直传EDM是目标，未建设前不当作现成路径；独立worker仅经验证后用于过渡，不能把500MiB流量导回整文件数组路径 |
| 平台/容灾 | ADS、ALB、WCM及跨Region控制能力须用真实操作单验证；旧DB写端、三服务后台/外呼隔离未证明时禁止备用Region开放写入，不能只改DNS |
| 下游状态 | 本地timeout、取消返回或WS发送完成不证明远端已停；缺失任务查询、幂等、取消确认及trace是建设项，不能现场假造能力 |

每次演练前，执行单必须填齐：artifact/镜像/配置及JDK、DB/Redis版本，精确实例/Region/AZ/地址和专用数据范围，规则/屏障ID、启动/查询/撤销步骤及TTL，独立观察人，已验证的摘流/回退包、[安全预算与恢复期限](tests.md#1-公共执行合同)、证据位置和应用/DBA/SRE/下游联系人。只用实际ADS操作，不假设Kubernetes。缺项仅可做只读诊断/无故障基线，相关注入BLOCKED。

<a id="joint-diagnosis"></a>
### 联合定位与责任交接

先区分受理、首有效事件、最终完成、Stop或恢复失败，再沿实际链逐跳核对：`Web→ALB→saas gateway→ChatService`，之后是`agentService统一chat→DomainAgent`，或`relayService→agentService MCP→下游`；意图故障另查intentService。服务角色图不改变仓库遗留适配类名。

定位卡固定记录时间窗、租户/功能、服务/实例/Region、可信trace/父子调用、runId/skillId/远端操作ID/配置版本、排队/鉴权/借连接/发送/返回/落库阶段、状态码/流内错误、耗时/attempt、资源和UNKNOWN。未取得对方日志时标盲区，超时只证明调用边界异常，不能直接认定DomainAgent内部根因。对齐CPU节流/GC/堆/direct、线程/队列、HTTP/JDBC池/锁、Redis回源及实际远端任务。由未参与注入的值班人按[T联合定位](tests.md#joint-localization)验证定位/交接时间；接报方保留协调责任至下一方确认接手。

事件指挥IC记录`t_detect/t_contain/t_fault_removed/t_service_recovered/t_backlog_reconciled`。先收紧证据指向的放大源，保留当前合法写Region正常聊天、Stop、回调和治理预算；旧Region控制请求不能绕过单写屏障。故障撤销后按25%/50%/100%已测安全负载各2分钟恢复并观察至少10分钟；资源回落与遗留任务收口完成才退出。所有通知由IC按既有渠道执行，本文不自动发送。

诊断优先一次低成本线程/堆概要与已有指标；JFR、NMT和heap dump先确认工具、启用条件及剩余盘/内存。濒临上限时不反复全量dump、不强制GC、不记录完整payload；证据按权限脱敏归档。

## 2. 13类活跃运行册

<a id="rb01"></a>
### RB01 — OOM、native memory与频繁GC

**关联：R01/R02/R04/R06/R07/R22；T01/T02/T04/T06/T07/T22；D01/D05/D06。主责：应用、SRE。**

- **触发/证据**：堆/RSS/direct、线程栈/FD或GC达到停止线，首事件/Stop恶化；对齐流速、恢复量、文件量和JVM/容器OOM记录，区分堆与非堆。
- **止血/禁止**：通过已验入口限制新WS握手、大文件、恢复和高频新Run；仍增长的单实例先摘流留Run/lease清单再替换。禁止全实例同时重启、只扩大Xmx/队列或依赖客户端断连停止任务。
- **恢复/核对**：依赖/input下降后分档放量；确认订阅、timer、许可、远端任务、临时文件随退出真实释放，FULL补读/no-store缺口单列。资源观察窗口内无增长、聊天/Stop及治理达标才退出；无法解释的增长升级性能/JVM排查。

<a id="rb02"></a>
### RB02 — CPU高位、JVM锁与线程停滞

**关联：R01/R04/R05/R07/R18；T01/T04/T05/T07/T18；D01/D02/D08。主责：应用性能负责人、SRE。**

- **触发/证据**：CPU节流/GC和长尾同时上升，或CPU不高但队列龄/Stop无进展；用限量profile及有间隔线程快照区分解析/日志、重试、GC、monitor、同池等待和慢IO。
- **止血/禁止**：限制对应输入/旁路/重连源；实例停滞按已验流程摘流替换并留栈。禁止`Thread.stop`、凭BLOCKED认定死锁、增加线程掩盖阻塞或全量payload日志。
- **恢复/核对**：锁owner与底层任务可推进、排队和GC回落后分档恢复；检查取消残留及积压释放。正常聊天/Stop达标、无热点持续增长才退出；DB锁联动RB03，下游重试联动RB05。

<a id="rb03"></a>
### RB03 — DB慢、连接耗尽、长事务与死锁

**关联：R05/R09/R18；T05/T09/T18；D02/D07/D08/D09。主责：DBA、应用。**

- **触发/证据**：连接借用超时、SQL/锁等待和事务年龄上升、治理停滞；记录DB事务ID/SQLSTATE/真实等待图及应用线程，区分池等待、锁环与慢SQL。
- **止血/禁止**：收紧查询/恢复/批删/管理批处理与新Run，保留管理及治理预算；DBA仅结束已确认异常事务并核验回滚。禁止扩池竞赛、直接改Run终态、关闭约束或重试事务中间SQL/外呼。
- **恢复/核对**：先确认旧事务回滚、锁/连接释放，再控制链、少量新Run、最后旁路；数据库恢复后保留积压检验二次回压。客户端超时不证明JDBC停止；提交未知先查事实。池/锁回基线、治理扫描完成且残留有结论才退出。

<a id="rb04"></a>
### RB04 — Redis异常、广播积压与回源

**关联：R04/R10；T04/T10；D03/D09。主责：Redis平台、应用/前端。**

- **触发/证据**：超时/重连、listener线程、广播lag或恢复请求突增；分别核对三服务缓存/锁/队列/持久状态职责，DB已有事件但客户端无帧不能当DB失败。
- **止血/禁止**：限制紧循环重连、Resume及缓存回源，保留DB余量；FULL受控补读、no-store显示缺口。禁止清共享Redis、全量从0恢复、未经验证切local-only/merge并宣称无损。
- **恢复/核对**：按实际拓扑恢复连通/订阅，逐批预热及放行补读，核对状态与注册/连接回落。各服务持久状态用途不明不得清空重建；lag和回源稳定、FULL缺口核对/no-store记录完成才退出。

<a id="rb05"></a>
### RB05 — DomainAgent、intentService、relayService及鉴权异常

**关联：R03/R16/R17/R19/R20/R21；T03/T16/T17/T19/T20/T21；D04/D09。主责：IC协调应用、agentService、Relay、第三方及鉴权方。**

- **触发/证据**：黑洞/429/5xx、首有效事件/流空闲超时、断流、连接/鉴权等待、取消残留；填写联合定位卡，区分统一chat、MCP和意图边界及健康skill对照。
- **止血/禁止**：按已验skill/模块/租户限额止血；无细分能力则明确服务级影响。Intent主路由默认首次＋3次、无退避，RELAY_FALLBACK会向Relay及共同agentService转移压力，必须核对降级容量；不能无限增加重试、绕过鉴权或把Relay当完全独立备用。UNKNOWN不跨provider自动重跑。
- **期限/取消核对**：统一chat原始chunk300s/总15m不等于有效首事件保证；Relay连接/握手/心跳与Run期限分开，60s idle不适用于普通问答。stop-path为空不发送取消，cancel吞错或Relay发送完成不证明工具停止；未确认任务继续列残留，不能只看本地终态。
- **恢复/核对**：每跳先验证鉴权、一次有效结果、底层任务及连接释放，再受控恢复旧积压和新流量；逐run/skill/远端操作核对仍运行、失败、已取消和UNKNOWN。健康链/Stop、总尝试量与资源稳定，未知任务有责任/期限才退出；内部日志不可得保留盲区并升级。

<a id="rb06"></a>
### RB06 — WS连接、订阅与客户端恢复风暴

**关联：R02/R22；T02/T08/T22；D05/D07。主责：前端、应用、入口平台；DBA/SRE协同。**

- **触发/证据**：总连接、握手/控制帧/重复订阅速率、发送队列字节或拒绝、连接关闭/重连和RECOVER_REQUIRED共同增长；按用户/租户/实例及客户端版本核对，区分空闲连接、慢消费、查库校验及长历史补读。保留FD、堆/native、GC、发送/注册表等待栈、DB等待及ALB/网关连接和游标轨迹；不能将16发送线程当16条连接限制。
- **止血**：先按已实现且验证的入口/应用策略限制新握手、控制/订阅校验及恢复并发，客户端退避抖动分批接入，保留正常聊天/Stop/心跳预算；有验证依据时定向处理慢连接。实例总连接、累计字节、控制速率及恢复配额缺失先列W03/W01/W12建设项；事故中只调用已存在且验证的入口限流或摘流能力，不虚构开关。
- **禁止**：全量踢连接制造重连、统一清游标、立即无限重试、扩大无界buffer或盲增线程/DB池、把断线当新Run重跑。关闭WS只解除事件订阅，不等于后台Run停止；未知执行先核对。
- **恢复/核对**：撤故障后以25%/50%/100%已验安全接入速率分档放量，少量验证建议游标与实际缺口，再恢复其余订阅；FULL与no-store分别核对，不把缺失正文虚构补齐。确认连接、前置查库任务、发送任务、订阅/timer及FD/堆/DB等待按`D_release/D_recovery`回落。
- **退出/升级**：至少观察10分钟，无断连重连循环及持续积压，健康聊天/Stop/治理达到签认目标才退出；本地失败边界不能定位或底层资源未退出时，升级应用、前端、入口平台和DBA共同处置并保留诊断。

<a id="rb07"></a>
### RB07 — EDM上传异常、文件资源及临时盘不足

**关联：R06，agent共进程传播联动R16；T06；D06。主责：应用、agentService、EDM、SRE，前端与DBA协同。**

- **触发/证据**：上传失败/超时、EDM分片或合并积压、重试量、未完成分片年龄、Chat/agent堆/盘/FD/连接增长，或技能查询/chat/MCP受拖累。关联上传操作、EDM文档标识及每跳阶段；分清当前Chat整读→agent分片转发和目标浏览器直传，Chat30s超时不证明EDM已停。记录实际JDK、direct/native与临时目录挂载，诊断及日志有界、不记录凭据。
- **止血**：按已实现并验证的规则限制新上传、分片并发/字节和重试，保留正常聊天/Stop、技能查询及完成核验资源；agent模块未隔离时说明摘流对chat/MCP的影响。授权、查询、取消和限流接口未实现的先列W06建设项，事故中不能假造操作。
- **禁止**：直接放开500MiB、未知结果盲重传整文件或重复合并、将直传失败自动导回Chat、清空EDM文档/整个临时目录、用普通S3对象替代EDM身份。EDM内部已分片不能作为Chat内存有界的证据。
- **恢复/核对**：EDM恢复后先查分片/合并/文档事实及本地登记，完成未知保留标识由责任方对账；仅重试合同允许的失败分片。先小文件和取消验证，再按已验安全配额逐档放量；核验docId、技能授权和附件引用，清理仅限本次确认无效的分片/临时文件，保留有效文档及历史引用。
- **退出/升级**：至少观察10分钟，上传及健康业务达到签认目标，堆/direct/native、盘、FD、连接和分片积压回落，取消/过期资源按期释放；UNKNOWN须有负责人及期限。EDM状态或清理无接口时升级EDM负责人受限人工对账，不能宣布全部完成；500MiB须T06真实规格通过。

<a id="rb08"></a>
### RB08 — 发布、探针及摘流异常

**关联：R08/R09/R18；T08/T09/T18；D07。主责：发布负责人、SRE、应用/DBA。**

- **触发/证据**：灰度后错误/队列龄上升、被摘实例仍接Run、health绿但业务停滞、全实例重启；保存镜像/配置/schema及入口变更时间。
- **止血/禁止**：暂停扩大发布，摘流问题实例并保留旧版容量；只有兼容证据充分才回滚应用配置。禁止同时停全副本、只依据health放量、将HTTP graceful shutdown当后台Run已排空。
- **恢复/核对**：验证受理/首事件/Stop/回调/恢复与治理，核对共库新旧协调域和DDL锁；应用回退不自动回退DDL/删除灰度数据。所有副本版本明确、后台与资源收口且观察流稳定才退出。

<a id="rb09"></a>
### RB09 — 取消未完成与遗留任务占用

**关联：R02/R03/R17/R21；T02/T03/T08/T17/T21；D04/D05。主责：应用、下游、DBA。**

- **触发/证据**：CANCELLING年龄、删除/实例退出后active任务、旧回调/重试持续占线程/连接；记录原Run/owner/远端操作及最后进度，区分仍执行、已结束和UNKNOWN。
- **止血/禁止**：暂停对应来源新重试/续接，合法主Region保留Stop/查询；优先正式取消并联合查任务。禁止直接改终态、删除队列掩盖残留、凭本地无记录重跑或无限补偿。
- **恢复/核对**：先查远端事实与本地有效owner，再通过已实现治理路径收口；没有补偿接口先建设并演练，不能事故中猜测改库。确认线程/订阅/HTTP/DB/许可真实释放，遗留数量和年龄回基线、正常聊天/Stop达标才退出；未知项有负责人和复核期限。

<a id="rb11"></a>
### RB11 — 共享依赖与一体agentService争抢

**关联：R09/R10/R16/R17，文件联动R06；T09/T10/T16/T17/T06；D09/D06。主责：三服务、DBA/Redis平台及IC，EDM协同。**

- **触发/证据**：多服务同时异常或agentService管理/查询/chat/MCP/文档上传互相拖慢；汇总全部副本与模块的CPU/堆/线程/连接/队列，不把受害方当压力来源。
- **止血/禁止**：先限制来源批处理、技能回源/高成本查询、恢复、MCP扇出或EDM上传分片，保护控制资源；缺模块级控制时注明服务级连带影响。禁止同时扩所有池、清共享Redis、把未来服务拆分当现成操作。
- **恢复/核对**：数据服务→可信配置/治理→chat/MCP→管理旁路逐步恢复，检测缓存回源及积压二次峰值；技能留存查询失败不能统一fail-open。三服务、五模块资源与正常链路均稳定，未知执行完成交接才退出，不能只签Chat恢复。

<a id="rb12"></a>
### RB12 — WCM、ALB与saas gateway入口

**关联：R11/R12；T11/T12；D10。主责：前端/WCM、入口平台。**

- **触发/证据**：白屏/chunk404、API返回HTML、WS/SSE中断、错误文根或入口不可达；分别探测静态主备、ALB、saas gateway（SaaS统一网关）和实际DNS落点。
- **止血/禁止**：已预发布且验收的独立非ADS静态源可受控切换；入口错误回滚具体规则并限重试。禁止只验index200、混杂版本、API走SPA兜底或单凭DNS改向开放备用业务写入。
- **恢复/核对**：新旧缓存浏览器完整启动/登录/聊天/WS验证，检查后台残留及重连资源；Region转移先RB14。静态/入口耗时达标且版本一致才受控回切，不自动来回抖动。

<a id="rb13"></a>
### RB13 — ADS运行面、控制面及AZ故障

**关联：R13/R14；T13/T14；D11。主责：ADS/SRE、三服务及数据平台。**

- **触发/证据**：容器/宿主/AZ故障或控制面、镜像/配置依赖失败；分别核对存量服务能力与重建/扩缩/发布能力，确认共同故障域。
- **止血/禁止**：暂停重复失败发布，摘流失效后端，按剩余AZ实测容量限制新业务；控制面不可用走已验独立管理通道。禁止因控制面故障重启全部正常业务或假定副本自动跨AZ。
- **恢复/核对**：校验镜像、配置、密钥引用和数据端点后逐批恢复，监测连接/缓存回源洪峰和远端遗留任务；区域内无法恢复才RB14。原Region平台恢复不等于恢复写权，Runtime不可靠接管不能自动重跑；完整链和剩余容量达标才退出。

<a id="rb14"></a>
### RB14 — Region单写接管与受控回切

**关联：R15；T15；D12；[接管图](deployment.md#dep05)、[回切图](deployment.md#dep06)。主责：IC、DBA、ADS/入口、三服务及下游。**

- **触发/证据**：主Region不可恢复或网络分区；“看不到A”不等于A已隔离。核对旧DB写端、存活后台/外呼、B复制位置/附件对象/配置与容量。
- **止血/门槛**：限制新写，记录在途；取得旧DB和三服务写入/后台/外呼独立隔离证明后才接管。缺证明B禁写；GSLB、Chat本地fencing和短暂失联均不能替代。
- **接管/禁止**：核对B实际数据及业务附件恢复点与批准损失→提升DB→准备Redis/映射→验证服务→允许符合条件业务→切全局入口。禁止双主、自动回切、重跑UNKNOWN或把异步复制写成RPO=0；隔离屏障不得自动TTL解除。
- **核对**：FULL恢复点内补读、no-store缺口与远端遗留分列；DB引用已到而对象未到/无法核对时阻断相关功能，不能称全功能恢复。记录入口/服务/遗留任务与容灾能力恢复时间。
- **回切/退出**：旧A保持隔离并预追平；强制隔离当前B写入及外呼后取得最终提交位点，A追平并核对附件/引用后才转移写权及入口。B未失权继续B；B已隔离/A未激活先证明无人写再恢复B；A已获写权则必须重新转移才能恢复B，不直接拨回DNS。唯一写主、旧域重连拒写、UNKNOWN/损失处置和复制/热备重建全部确认才退出。

## 3. 12组演练执行单

全部演练沿用[公共执行合同](tests.md#1-公共执行合同)：默认5分钟基线、故障60秒/上限120秒、屏障30秒上限，撤销后至少观察10分钟。单故障通过后才叠加；每组明确注入者、独立观察/撤销人及具体平台操作。资源超线、正常聊天/Stop超签认期限、重复任务放大、影响越界或撤销失控立即停止；Region保护屏障继续有效。表内“验证”均为待执行目标。

### D01 — 快流慢库、CPU与JVM资源

**T01/T07；RB01/RB02；应用/测试/SRE。** 按帧速率阶梯压测Relay和统一chat，分别增加落库200ms、阻塞30秒、深层/大帧与错误日志，单项通过后叠加60秒。独立观察CPU节流、分配/GC、堆/direct、队列及Stop；到安全线撤输入和屏障，按档恢复保留积压。稳定档运行至少2小时验证增长斜率。证据须含热点、队列字节、取消/退出释放和恢复后二次峰值；不能以未实际OOM判成功。

<a id="d02"></a>
### D02 — 连接耗尽、DB/JVM锁与治理

**T09/T18；RB03/RB02；DBA、应用/测试。** 预列真实SQL/锁序，独立占连接/锁60秒，同时观察heartbeat/Stop；双事务在实际首锁后交错，JVM同topic/WS dispose/Relay发送关闭用可撤屏障，保留管理通道。根据等待图和线程栈确认实际命中，不相交或无环须如实记录；另测事务内Redis慢与客户端先超时。解除屏障/回滚登记事务后确认JDBC实际退出、锁/池回落、治理积压消退；只在安全幂等且已回滚时测试完整事务有界重试。

### D03 — Redis消息风暴、中断与重连

**T04/T10；RB04/RB11；Redis平台、应用/前端。** 专用topic提高发布率、listener暂停30秒，再单独断订阅60秒；真实拓扑切换按管理员单执行，不能清共享Redis。先恢复少量连接/缓存回源，再分批恢复订阅与FULL补读，观察三服务DB回源和listener线程/队列。no-store缺口明确记录；保存实际拓扑、重连率、seq缺口、回源与资源回落，状态用途不明则不执行清空恢复。

<a id="d04"></a>
### D04 — 下游黑洞、重试降级与取消残留

**T03/T17/T19/T20/T21；RB05/RB09；Chat、agentService、Relay、第三方、鉴权及测试联合。**

1. 先验证真实调用边、当前期限、各跳尝试/扇出与可对账测试操作；健康skill/正常聊天/Stop作观察流，缺远端查询/取消确认能力记BLOCKED，不能只靠本地mock验收。
2. 分别对鉴权、统一chat→DomainAgent、Intent、Relay以及MCP边界注入黑洞、429/5xx和首帧前/后断流60秒，每项复位后继续；默认长期限另签执行窗口，短配置仅验证机制。
3. Intent比较默认4次即时尝试及RELAY_FALLBACK/FAIL_RUN，记录故障请求转移至Relay/agentService的增量；先主路由，候选有退避的旁路单独测，禁止混淆。
4. Relay覆盖Upgrade/config无ready、半开、无终态关闭；MCP逐层计数实际执行。Stop后一个工具忽略取消30秒，另让旧session Stop迟到15秒并观察后续Run资源，区分本地完成/发送完成/paused/远端任务停止。
5. 按执行方逐个结束测试任务，撤规则但保留可观察积压，25%/50%/100%恢复；收集尝试放大比、鉴权/池等待、取消残留、定位/交接时间与正常链SLI。无可解释资源释放或未知执行处置时不能结束为成功。

### D05 — WS连接/订阅/Resume风暴与实例退出后收口

**T02/T08/T22；RB06/RB09，内存事故联动RB01；前端、应用、入口平台/SRE、DBA。** 按T22签认预算，先分开验证大量空闲连接、活跃推送、慢消费和60秒高频握手/控制/重复订阅；观察前置查询配额、发送拒绝和正常聊天/Stop/心跳。再用长历史与实时发帧叠加断网30秒和多页签重连，对比即时重连与目标退避/抖动。单项通过后才覆盖commit前、commit后publish前退出一个实例，另停止方在CANCELLING后退出；新连接转移不能绕过实例/租户/集群合同。资源越线、观察流失败或撤销失控立即停止，禁止全量踢连接、清游标或重发Run制造假恢复。撤负载/慢读/断网并按安全速率分档接入，确认FULL恢复点补读、no-store缺口、连接/控制任务/订阅/timer/FD/许可及远端残留收口，至少观察10分钟并保存预算、实际曲线、客户端重试量和积压年龄。缺少限额/观测/撤销能力的子项保持BLOCKED，演练当前NOT_RUN。

### D06 — 500MiB EDM直传与故障后资源收口

<a id="d12"></a>
### D12 — Region接管、分区安全与回切

**T15；RB14；IC、DBA、ADS/入口、三服务/下游及独立观察人。**

1. 固定A主B热备、实际DB异步复制、业务附件与配置恢复点及阶段期限；B只允许健康探测。预先空载验证旧DB写端、三服务后台/外呼隔离，保护屏障不自动过期；无法验证则只可证明安全拒绝接管，整体放行BLOCKED。
2. 分别演练计划接管、A仍存活分区、复制滞后60秒和附件对象落后；取得A隔离回执，再核对B恢复点/批准损失、提升DB、准备Redis/映射、激活并验证服务，最后开放符合条件业务及GSLB入口。超RPO/对象不全阻断相关放行；故障TTL撤销不恢复A写权。
3. B按档接流并处理恢复积压；A网络恢复但继续隔离，验证旧DNS/长连接、迟到Stop/回调/排队外呼无法重启旧执行。FULL/no-store、远端UNKNOWN分别对账，禁止自动重跑未知任务制造峰值。
4. 回切先预追平A，在QUIESCING保留迟到终态/回调；强制隔离B写入与外呼后取得最终提交位点，证明A追平该位点及附件引用后再激活A和切入口。分别验证隔离前迟到提交已包含、隔离后写入被拒，提前水位不能代替最终证明。
5. 失败按最后确认主权保持安全单写；新主已写不能只回拨DNS。出现双写迹象停止新业务写并由IC/DBA确定安全端；保护屏障继续生效。重建复制/热备，所有未知/损失有负责人后收尾。

必须保存阶段签认、隔离/拒写回执、最终提交位点及追平证明、附件/DB引用差集、配置/manifest、远端任务、DNS实际落点、资源峰值和入口/服务/遗留任务/灾备恢复时间。仅首页可用或DB提升成功不能关闭R15。

## 4. 复盘与放行

每次执行保留独立记录：`D/T/子项/源码与环境版本/配置/执行人/状态/发现-止血-撤销-服务恢复-积压收口时间/失败拒绝与残留数量/资源峰值/证据/未关闭项`。故障未被检测要记录检测缺口，后续成功不能覆盖首次失败。

成功须同时证明影响受控、撤销有效且未撤保护、资源有界并真实归还、正常聊天/Stop和遗留任务在签认目标恢复，值班人可按证据定位与交接。安全线触发后终止保留FAIL；能力缺失为BLOCKED；未执行为NOT_RUN。未具指标、限额、查询、取消确认、drain或平台隔离先进入加固任务，不能由运行册文字代替已实现能力。
