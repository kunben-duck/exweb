### 共同处置顺序

事件指挥（IC，由应用负责人或当值SRE担任）统一记录 `t_detect/t_contain/t_fault_removed/t_service_recovered/t_backlog_reconciled`，其中移除故障不等于恢复。应用负责人检查业务状态，DBA检查连接/锁/索引，SRE负责路由/实例/资源，下游负责人查真实副作用，前端负责人查恢复游标，测试人员记录证据；安全/存储负责人参与RB10。

先核对影响面与正在进行的发布，再限制导致放大的入口，同时保留**当前合法写Region**的Stop、内部回调和必要状态读取路径。Region切换时旧Region的回调、后台写和外呼也必须受隔离，不能以保留控制链路为由绕过单写屏障。不能一刀切阻断所有接口后把HTTP错误率下降记为恢复。任何对外通知由事件指挥通过既有渠道执行，本文件不自动发送消息。

可用的只读诊断示例（在对应运行宿主、具备JDK工具且值班权限允许时；`HA_PID`和目录必须由执行单明确提供）：

## 2. 十四类故障运行册

<a id="rb01"></a>
### RB01 — 堆、native memory与频繁GC

**关联：** R01/R03/R09/R12，T01/T03/T09/T12/T26，D01/D05/D06。

1. **触发与影响确认**：heap/RSS/direct memory或线程/FD达到执行单停止线，GC时间增加、首事件退化、进程被OOM终止。对照请求量、历史补读量、入站帧、上传/下载、Redis入站与平台线程数，区分堆对象、direct buffer和线程栈；确认是否单实例、租户或全实例。
2. **止血**：通过已验证网关规则先限制恢复、文档和高频新Run来源；观察流和控制接口保留。若单实例继续增长，先摘流，记录该实例持有的Run/lease，截取一次低成本诊断后按预案替换实例；一次只操作一个实例并检查剩余容量。
3. **禁止动作**：不持续扩大Xmx/队列、无限重试、全实例一起重启或删除Redis事实替代物；不用客户端断开代替Stop；未提交结果不能因本地进程消失而声称完成。
4. **恢复步骤**：确认依赖恢复/输入速率下降后，小批恢复新流量；有界队列及字节上限未修复时保持入口限制，记录受影响功能；必要的限额配置通过已测配置发布，不假设热更新。
5. **数据核对**：按摘流前清单逐个检查Run、Execution、Interaction、异步任务，FULL补读验证最后seq；no-store记录不可恢复结果。确认下游仍执行的任务和文档孤儿对象。
6. **退出与升级**：资源在观察窗口内回落且无持续增长，Stop/首事件和治理满足签认目标，遗留任务全部有结论。应用负责人主责，平台SRE处理宿主OOM，DBA/下游负责人处理恢复阻塞；无法解释增长转RB02和资源专项profile。

<a id="rb02"></a>
### RB02 — CPU高位、线程停滞、序列化与GC负担

**关联：** R01/R09/R11/R16/R25/R26/R38，T11/T16/T25/T26/T38，D01/D02/D08。

1. **触发与影响确认**：CPU/容器节流持续超过停止线且长尾恶化，或CPU不高但任务/WS/Stop无进展、排队龄持续上升。以CPU采样、分配率、GC、两次有间隔的线程快照/JFR判断JSON/日志、重试、锁竞争、慢IO或宿主限额；记录monitor owner/waiter和锁内emit/dispose回调。线程BLOCKED不等于已证明死锁，CPU繁忙本身不是死循环证据。
2. **止血**：限制证据指向的大帧/高频事件、历史查询、恢复或订阅变更来源；下游5xx/黑洞联动RB05。核对是否局部topic锁还是WS实例注册表锁，避免全实例同时重连；无法解除的实例级停滞按已验证流程摘流，留诊断与Run清单后受控替换实例。可选旁路按发布预案关闭，已在途任务继续跟踪。
3. **禁止动作**：不增加线程数掩盖瓶颈，不全量记录大payload，不连续heap dump或强制GC；不使用`Thread.stop`、解锁猜测或只杀DB会话处置JVM锁，不在无profile时全局关闭校验/日志。
4. **恢复步骤**：确认热点/阻塞解除、回调退出和任务可推进后分档放量，每档观察CPU节流、GC、首事件、Stop、completed Run数量、队列龄及订阅计数；等待线程减少但原任务未收口不能退出。再次停滞或热点重现则退回上一档，保留输入及交错用于T26/T38。
5. **数据核对**：检查因超时/取消导致的未终态任务、重试副作用与seq缺口，防止“CPU恢复但任务重复/丢失”。
6. **退出与升级**：资源及主链路恢复且无队列持续增长；应用性能负责人主责，平台确认CPU quota/宿主竞争，前端/下游共同定位重连或重试放大源。

<a id="rb03"></a>
### RB03 — 数据库慢、连接耗尽、锁等待或死锁

**关联：** R02/R07/R10/R11/R13/R15/R23/R25/R38，T02/T07/T10/T11/T13/T15/T23/T25/T38，D02/D07/D08。

1. **触发与影响确认**：Hikari pending/acquire timeout、事务年龄、锁等待、SQLSTATE/死锁报告上升，heartbeat失败或lease余量不足。DBA保存真实等待图、事务ID、SQL指纹/顺序，区分应用死锁、DB锁等待、执行器饥饿与连接池等待；潜在锁序风险不等于已复现死锁。
2. **止血**：收紧恢复/搜索/树/批删/旁路入口及新Run，暂停非必要批处理，保留当前主Region控制与DB管理预算。仅由DBA终止已确认的异常阻塞事务并核验回滚；控制连接被占满时使用已验证独立管理通道。不能假定应用已有治理专用池，也不因一个模块超时统一摘除全部三服务。
3. **禁止动作**：不无限增池、不关闭唯一约束/fencing、不直接UPDATE Run终态、不无计划重建索引；不能单独重试事务中间SQL或重复外呼。Reactive/client timeout不证明JDBC取消或事务回滚，不能在旧事务未核对时重放写请求。
4. **恢复步骤**：确认阻塞SQL结束、受害/超时事务完整回滚、锁和连接释放后，先状态/Stop/heartbeat，再少量新Run，最后旁路和批处理。按25%/50%/100%实测安全负载阶梯核验旧队列恢复无二次回压；DB切换后同时确认旧连接与失败事务，而非只验新连接。
5. **数据核对**：按T38核验Run/Execution/Interaction/Binding/Event/Message与删除的原子性，区分已提交、未提交和UNKNOWN；事务提交后通知失败与事务回滚分开处理。保存异步线程/TX/连接边界及DB锁序证据；发现锁序环需由应用/DBA修正并复测，不能靠持续杀会话关闭风险。
6. **退出与升级**：池等待与锁归零或回到已解释基线，Watchdog可完成后续轮次，正确性和未知提交处置完成；DBA负责数据层，应用负责事务/调度，SRE负责网络/容器。锁/线程与远端阻塞相互影响时联动RB05/RB11，不以DB绿灯关闭。

<a id="rb04"></a>
### RB04 — Redis不可用、订阅中断或实时广播积压

**关联：** R04/R07/R09/R16，T04/T07/T09/T16，D03。

1. **触发与影响确认**：Redis超时/重连、广播lag、RECOVER_REQUIRED突增，前端无新帧但DB已有新事件。区分缓存、取消标记、恢复锁优化与Pub/Sub问题；确认FULL和no-store受影响用户范围。
2. **止血**：限制前端紧循环重连和HTTP补读，网关使用已验证恢复限额；保留DB余量。实时故障明确反馈用户，FULL按状态+游标补读，no-store保持“可能无法补回”的语义。缓存miss风暴时限相关入口，不能为命中率清空全缓存。
3. **禁止动作**：不把Redis当事实源重建终态；不把`local-only`或粘性路由当跨实例无损保证；不把`merge`当自动安全降级；不让所有客户端立即afterSeq=0。
4. **恢复步骤**：SRE按现场清单验证Redis连通、实际拓扑与订阅重建，先恢复少量topic观察消息顺序，再逐步恢复补读；应用对缓存值重新核验DB状态。listener线程异常时按RB01处置。
5. **数据核对**：FULL比对已提交/广播/消费seq和最终状态；no-store单独统计业务结果缺口；检查暂停期间旧取消标记/恢复锁是否影响状态，禁止批量删除不明key。
6. **退出与升级**：实时lag和恢复量回落、FULL缺口补齐、no-store缺口已记录、DB回源压力正常；平台Redis负责人主责，应用/前端负责恢复，下游仅处理被错误重复执行的任务。

<a id="rb05"></a>
### RB05 — Relay、agentService、DomainAgent、Intent或鉴权异常

**关联：** R05/R06/R16/R25/R36/R37，T05/T06/T16/T25/T36/T37，D04/D09。

1. **触发与影响确认**：连接/首有效事件/idle/总期限超时、401/429/5xx、鉴权或池等待、Stop未知结果增加。先填[联合定位卡](#joint-diagnosis)，区分Chat→agentService chat与Relay→agentService MCP，再查实际工具/DomainAgent；Intent为独立依赖。记录原始chunk与有效事件差异、池/线程/排队与真实执行事实，不能凭超时认定下游宕机。
2. **止血**：用已验证入口限制受影响skill/模块/租户的新逻辑请求；若不能细分，按已验收服务级范围处置并明确连带影响。只有合同允许且结果明确时才改路由。Relay MCP放大先限制扇出来源和新Run，不能假设已有MCP熔断动态开关；session级迟到Stop未排除时暂停该会话续接并联合核查命令。
3. **禁止动作**：不跨provider盲重放、不增加逐层重试或绕过鉴权；不把日志retryable当授权重试；不记录大payload排查；不把`stop-path`为空或cancel异常被吞后的本地完成称为远端取消成功。关闭Relay Bean是配置发布，不是当前请求熔断。
4. **恢复步骤**：分别验证鉴权、借连接、一次有效结果及Stop远端确认；核对取消后底层任务/线程/连接真实退出，未退出的仍列残留。下游确认未决任务与Stop代次/顺序后才恢复续接；恢复按25%/50%/100%安全负载，保留积压观察，避免解除故障后重试集中释放。
5. **数据核对**：关联本地Run、父子调用、skill/配置版本、runtime session/工具任务与异步回调，分别记录失败、已取消、仍执行和UNKNOWN；无法查询远端时列出受影响请求及责任人，不推定未执行。停止与自然完成竞争以真实终态为准。
6. **退出与升级**：各跳SLI、放大比、资源释放和观察流达标，UNKNOWN与取消残留有明确处置；IC协调Chat/Relay/agentService、鉴权和实际第三方共同签认。接报方交出完整证据且下一方确认后再交接；定位/接报期限按W11，内部日志缺失或代次证据不足时保留阻断。

<a id="rb06"></a>
### RB06 — 恢复风暴、慢客户端及多页签

**关联：** R03/R20，T03/T20/T27，D05/D07。

1. **触发与影响确认**：Resume并发/查询行数、连接创建、RECOVER_REQUIRED、重复subscribe和WS发送超时同时增长；识别长历史用户、多个标签页、网关idle截断或客户端错误游标。
2. **止血**：网关限制HTTP Resume及WS握手/订阅的来源频率，前端部署已有可用的退避抖动策略；无前端策略时优先入口限流与用户可见等待，不能声称服务器已具备独立HTTP恢复配额。保留Stop及正常聊天预算。
3. **禁止动作**：不要求所有用户清游标，不重发NEXT代替重连，不把HTTP200的ACCESS_DENIED当成功，不任意放大live buffer。
4. **恢复步骤**：优先恢复少量客户端；按服务端建议游标重新订阅并按事件身份去重，再分批恢复其余；确认网关idle/总期限与流式协议匹配，清理已关闭连接注册。
5. **数据核对**：每Run核对已消费最大seq与真实缺口，不能只比较最大数字；FULL补回缺失，no-store明确缺口，已读水位仅在实际消费后推进。
6. **退出与升级**：恢复流量降到基线、无持续缺口/重连循环，主链路稳定；前端和应用主责，SRE调整验证过的网关限制。生产前端必须单独验收，联调样例不能替代。

<a id="rb07"></a>
### RB07 — 存储异常、慢文件流、临时磁盘满及孤儿对象

**关联：** R12/R21/R22，T12/T21/T22，D06。

1. **触发与影响确认**：上传/下载超时、FD/存储连接增长、临时磁盘不足、对象与DB记录差异。先确认实际provider，API Store整文件数组与OBS流式路径分别定位。
2. **止血**：使用已验证入口限制新上传/下载及文件大小，保留元数据/状态查询；容量未验收时恢复到已测文件上限，不临时扩大到500MiB。存储并发许可在接收/临时复制之后取得，降低它不单独保护临时盘；入口控制缺失则明确限制上传功能。慢客户端导致的在途流由已验证连接关闭机制逐步清理。磁盘满时只清理明确失效的测试/临时文件，先确认没有在途引用；真实事故按存储清理策略执行，不能泛删临时目录。
3. **禁止动作**：不把文档软删除当物理对象已删除；不在未知上传结果时盲重传；不清bucket/对象前缀外文件；不切本地磁盘当多实例持久存储。
4. **恢复步骤**：存储连接/TLS/磁盘修复后用小文件完整上传、登记、下载、取消验证；再分档恢复并发及文件大小，观察许可是否覆盖整个流生命周期。
5. **数据核对**：按操作标识、对象key、checksum、上传时间和文档记录核对，先确认没有有效引用再清孤儿；当前缺持久操作ID/自动对账时以限定前缀清单由存储与应用共同处理，不假称有一键补偿接口。
6. **退出与升级**：FD/连接/磁盘恢复、流与底层复制/SDK任务关闭可验证、孤儿对象和未知上传全部有结论；500MiB仅在T12真实规格容量通过后放开；存储/SRE主责，应用处理生命周期，信任/TLS问题转RB10。

<a id="rb08"></a>
### RB08 — 发布、探针及摘流异常

**关联：** R02/R04/R13/R14/R15/R27，T15/T27，D07。

1. **触发与影响确认**：灰度后错误/终态延迟增加、旧实例仍接新Run、readiness绿而业务不可用、全实例反复重启或恢复峰值。核对artifact、配置、数据库迁移与网关变更时间。
2. **止血**：立即暂停扩大灰度和后续发布；摘流有问题的新实例，保持旧版本可用副本与控制链路。确认DB/协议向后兼容后按执行单回滚应用和对应配置；没有兼容证据则先隔离流量，由负责人确定前向修复。
3. **禁止动作**：不同时终止全部实例、不仅依据默认health恢复流量、不关闭fencing/唯一约束；不能假定Spring HTTP graceful drain自动等所有后台Run完成，不能把回滚jar等同回滚DDL。
4. **恢复步骤**：正确版本先用少量流量验证受理、首事件、Stop、callback、WS恢复及后台治理；检查旧owner不能继续提交；配置和索引确认后再逐实例恢复。
5. **数据核对**：列出发布窗口内Run、WAIT/RESPONDING/async与已删除active，检查每个都有明确终态/等待语义；核对兼容DTO、恢复游标和旧客户端错误行为。
6. **退出与升级**：所有副本版本明确、实例摘流验证通过、观察窗口内不再重启放大、遗留任务对账完成；发布负责人/SRE主责，DBA、应用和前端共同签认。

<a id="rb09"></a>
### RB09 — 状态不一致、重复执行与未知外部副作用

**关联：** R04/R08/R14/R17/R18/R19/R24，T04/T08/T14/T17/T18/T19/T24，D03/D05/D08。

1. **触发与影响确认**：重复活动Run/终态、CANCELLING年龄超标、旧owner写入、删除后仍可恢复、部分分支、分享撤销遗漏、WeLink重复/未知投递。保存原始提交时间和关联标识，禁止先删证据再修复。
2. **止血**：对受影响会话/写入口施加精确入口限制，暂停自动重试与外部重发；通过已有状态/历史接口和DB只读快照判断事实。活跃Run优先使用正式Stop，若Stop结果未知按RB05联合核查远端。
3. **禁止动作**：不手工改Run终态或删唯一约束，不假设本地记录不存在等于远端没收到，不以撤销分享声称已召回WeLink消息，不重建Run来“修复”客户端显示。
4. **恢复步骤**：数据库事实与外部任务对账后，使用已有幂等/条件更新路径补操作；当前没有可用补偿接口的缺陷，先形成修复脚本/代码及演练证据再执行，运行册不授权猜测性的直接改库。状态恢复后再放开写入口。
5. **数据核对**：逐逻辑请求统计0/1/多次实体和远端副作用；校验Session状态、leaf、Run/Execution owner版本、终态、Interaction和share生命周期；无法确认的保持UNKNOWN并列责任人与复核期限。
6. **退出与升级**：没有未解释的重复/悬挂/权限绕过，UNKNOWN已明确业务处置；应用负责人主责，DBA、前端和下游共同对账，涉及用户可见错误由业务负责人确认补偿措施。

<a id="rb10"></a>
### RB10 — 文档信任边界与存储TLS

**关联：** R21/R22，T21/T22，D06。

1. **触发与影响确认**：可信provider引用被客户端metadata改变、附件指向异常目标、OBS接收错误证书或hostname。区分已确认错误行为和未证实的越权/泄露，保存限定范围证据。
2. **止血**：入口暂阻断受影响metadata编辑/附件使用/存储路径，保留必要状态读取；隔离异常endpoint，按实际证据协调凭据处置。当前没有白名单或严格TLS现成开关，不写“打开开关即可恢复”。
3. **禁止动作**：不以关闭证书校验恢复可用性，不允许客户端指定truststore/可信URL，不用生产文件验证可疑端点，不在不明归属的metadata上批量覆盖providerDocument。
4. **恢复步骤**：部署保留服务器可信字段的修复与显式证书/hostname校验；核对企业CA和endpoint SAN，执行T21/T22正负例后逐步恢复入口。旧客户端合法业务metadata需兼容验证。
5. **数据核对**：限定窗口内比对文档provider引用、对象归属、下游附件参数及审计记录；是否发生外部访问/跨用户影响由实际日志和下游证据确认，未能证明的保持待调查。
6. **退出与升级**：错误引用无法影响可信附件、错误证书被实际SDK拒绝、合法路径成功，影响范围和修复记录完整；安全负责人、存储负责人及应用负责人共同关闭。

<a id="rb11"></a>
### RB11 — 三服务共享依赖与一体agentService模块争抢

**关联：** R28/R29/R30/R36/R37，T28/T29/T30/T36/T37，W11 / D09、D04；图[DEP01](deployment.md#dep01)、[DEP02](deployment.md#dep02)。三服务负责人、DBA/缓存与实际下游联合处置，合同统一见[W11](risks.md#w11)。

1. **触发与影响确认**：三服务同时异常、agentService管理/技能查询/chat/MCP彼此拖慢、DB池/锁等待、Redis热点/淘汰/回源或映射版本不一致。按服务全部副本和一体模块汇总资源；用[联合定位卡](#joint-diagnosis)区分压力来源与受害方，MCP扇出/逐层重试按T37计数，不将所有超时归Chat或DomainAgent。
2. **止血**：通过已验证入口/作业操作限制被证据定位的压力来源，暂停非必要管理批量操作、高成本恢复与新增扇出，保留合法主Region治理。模块没有独立开关时不可临时宣称可单独熔断；服务级摘流需明确chat/MCP/查询一同受影响。映射不可用仅在有效期/撤销合同允许的可信缓存范围续服，未知执行停止自动重试。
3. **禁止动作**：不同时扩大三服务或所有模块线程/连接池、不清共享Redis、不把Chat“Redis非事实源”推广给其余服务；不临时改变skill目标、不把agentService timeout当下游未执行、不把未来三拆视作现成止血操作。
4. **恢复步骤**：数据能力、线程/HTTP池与映射查询先验证，再恢复Stop/回调等控制路径，随后chat/MCP，最后管理批量操作与旁路；每档检查积压释放/缓存回源与总配额。旧任务未退出不能仅凭容器健康恢复全部流量，Redis持久状态职责不明禁止清空重建。
5. **数据核对**：每个逻辑请求关联映射版本、实际任务及回执、Chat/Relay事实，逐服务核对提交标记与Redis状态；UNKNOWN经实际执行方确认后处理，不盲重跑。未来P拆分后的管理、tool和agent端分别核查版本/身份/配置，不借用C通过证据；Region问题按RB14处理。
6. **退出与升级**：三服务和agentService四模块的业务/控制/资源均稳定，回源和MCP放大受控，映射一致且未知任务有处置；不能只签Chat首事件恢复。IC保留协调至各方完成明确交接，DBA/缓存解决共享层，agentService/Relay/下游签认执行和取消结果。

<a id="rb12"></a>
### RB12 — WCM静态源、ALB文根及GSLB入口异常

**关联：** R31/R32，T31/T32，W12 / D10；图[DEP04](deployment.md#dep04)、[DEP03](deployment.md#dep03)。主责为WCM/前端和入口平台负责人。

1. **触发与影响确认**：浏览器白屏、chunk404/版本不匹配、API返回HTML、WS/SSE中断、错误文根或区域ALB不可达。分别探测WCM主源、独立备用源、各Region ALB及GSLB实际解析；判定静态问题、单路径错误还是Region入口故障。
2. **止血**：静态故障按已验证源站配置将流量转向非ADS备用托管源，使用对象存储中已预发布的完整manifest，不临时构建/上传作为主要恢复路径。路由错误回滚对应ALB配置；停止放大POST重试与客户端紧循环重连。
3. **禁止动作**：不把静态备用回源到故障ADS、不只检查index.html 200、不发布混杂版本、不把API错误导向SPA fallback；ALB失效不代表旧Region已失去写权，不能单凭GSLB切到备用就开放其写接口。
4. **恢复步骤**：按DEP04逐步验证备用源TLS/文根/资源/运行配置，再从冷缓存及旧缓存浏览器跑完整业务与WS；ALB区域故障需要转移写入Region时先执行RB14单写接管，完成后再切GSLB/DNS并验证实际收敛。静态源可独立恢复时不扩大为全Region切换。
5. **数据核对**：保存前后manifest哈希、路由版本和浏览器网络记录；核对超时期间重复NEXT/agentService转发模块调用/回调和未消费事件。FULL仍受有效恢复点约束；旧DNS和已有连接必须命中安全响应，不能绕过旧Region隔离。
6. **退出与升级**：新旧浏览器完整链路、三服务路由正负例和长连接恢复通过，静态/入口恢复时间满足目标，才受控回切静态主源；不自动来回切换。WCM负责人确认源站，前端确认资源兼容，ALB/GSLB负责人确认路由/解析，业务写权由IC/DBA按RB14确认。

<a id="rb13"></a>
### RB13 — ADS控制面、运行面与单AZ失效

**关联：** R33/R34，T33/T34，W13 / D11；图[DEP02](deployment.md#dep02)、[DEP03](deployment.md#dep03)。主责为ADS/SRE，三服务及数据平台联合。

1. **触发与影响确认**：容器/宿主退出、某AZ不可达、控制面操作失败、镜像/配置/密钥依赖异常。分别确认存量业务是否还能服务、是否还能重建/扩缩/发布；两Region控制面/运行面独立是架构约束，实际共同依赖仍需排查。
2. **止血**：暂停发布与自动扩缩放造成的重复失败，ALB摘除已确认失效后端；按剩余AZ实测容量限制新业务，保留治理与数据服务预算。ADS操作不可用时使用执行单中已验收的独立隔离通道，不能虚构一键重建/灾备按钮。
3. **禁止动作**：不因控制面故障就重启仍正常的所有业务，不假定副本自动跨AZ，不把容器重新起来当旧Runtime接管成功，不依赖宿主临时文件恢复业务；不将旧Region平台恢复等同恢复其写权。
4. **恢复步骤**：区域内先恢复必要运行资源/网络，核验镜像digest、配置/密钥版本、服务身份和数据端点，再逐批恢复三服务及ALB后端；AZ回接观察连接风暴。整个Region运行面不可用或无法在目标内恢复时，进入RB14，不直接绕过数据与主权检查切流量。
5. **数据核对**：逐服务对账中断时的任务/映射/副作用；Relay内存session丢失与DB历史可读分别记录，Runtime无法可靠续接的任务以确定失败/中断或UNKNOWN处理。FULL补有效恢复点内历史，no-store不承诺重建正文。
6. **退出与升级**：剩余及回接AZ负载满足目标，三服务业务与治理均恢复，无旧owner写入、无未解释的UNKNOWN。ADS负责人提供运行/控制面恢复证据，SRE/DBA/缓存负责人提供容量和拓扑，三服务负责人确认任务处置。

<a id="rb14"></a>
### RB14 — Region单写接管、分区隔离与受控回切

**关联：** R35，T35，W14 / D12；图[DEP05接管](deployment.md#dep05)、[DEP06回切](deployment.md#dep06)。IC统一指挥，DBA、ADS/入口、三服务和下游负责人共同签认阶段门槛。

1. **触发与影响确认**：主Region运行面/入口不可恢复或区域分区；核对A是否仍有存活实例、DB写端、定时任务、外部调用和旧连接。区分“探测不到A”和“A已被可靠隔离”；备用B的复制位置、映射/对象/静态版本、容量和依赖连通均纳入接管清单。
2. **止血与单写门槛**：限制新写并记录在途及UNKNOWN；执行DEP05-03/04，取得旧三服务后台/外呼和旧数据库写端的独立隔离证明。证明缺失即执行DEP05-14：B保持禁写，不因RTO压力越过。GSLB切换、旧实例暂不响应、Chat本地fencing均不能替代该证明。
3. **禁止动作**：不自动提升双主、不自动回切、不重跑未知agentService转发模块/Relay/DomainAgent任务；不将异步复制称为RPO=0，不为no-store新增正文持久化；不在提升后简单拨回DNS，不将隔离屏障设为120秒自动过期。
4. **接管步骤**：隔离证据通过后，按DEP05-05/06确认B数据库及业务附件对象恢复点、允许损失及缺口；对象版本/内容、DB文档引用与租户/访问权限必须核对，不能只验证静态发布包。超批准RPO或无法核对时阻断相应接管放行。DBA提升B后检查三服务数据端点/映射、Redis、后台与外呼主权；受控探针通过才开放符合条件的B业务，最后改GSLB/DNS。每阶段超时暂停扩流并保持安全单写。
5. **数据核对与用户结果**：比较旧主已提交标记和目标实际恢复集，分别列DB事实、agentService管理模块映射、业务附件对象/DB引用/权限及外部副作用差异；DB引用已到而对象未到必须列明，批准的对象损失也要隔离受影响附件上传/下载/引用功能，只能报告限定范围恢复，不能报全功能恢复。FULL只恢复有效点内历史。Runtime不可靠接管，UNKNOWN由远端查询/对账，不自动重跑；记录页面、入口、业务及遗留任务恢复时间。
6. **受控回切**：A修复后维持隔离并预先追平；DEP06-05只能预收集水位，QUIESCING时仍可能有迟到callback/终态提交。DEP06-06强制隔离B数据写入及外呼后，DEP06-07必须取得或证明**隔离后的最终提交位点**并让A追平校验，同时通过业务附件对象恢复点、DB引用/权限核对，才可DEP06-08激活A。提前追平不替代最终检查。失败执行DEP06-13：B未失权继续B；B已隔离/A未激活先证明无人写再恢复B；A已激活必须重新转移主权才能恢复B，不一概拨回。
7. **退出与升级**：唯一主Region证据明确、旧域重连/旧DNS/迟到消息均不能写或触发旧副作用，实际RPO及损失集完成签认，UNKNOWN有处置，跨域复制与热备能力已按新主重建。IC、DBA、三服务和下游共同关闭；任何双写迹象立即停止新增业务写并由IC选择可证明安全的单写端，不能靠平均指标宣布恢复。

## 3. 演练通用执行协议

以下为12组演练的固定执行步骤。D06文档迁移/直传/worker、D07同库灰度协调和D10–D12容灾目标子项均依赖P能力；前置未实施或操作未验证时不得进行对应注入，更不得签PASS。同一编号包含多个子场景时，**每个子场景恢复到已确认的安全状态后再开始下一个**。D12已经转移写权时不能用“复位”自动切回旧主，只能另走受控回切。完成单故障验收后，才允许在相同影响范围内追加已列明的叠加步骤。不得借“演练方案”扩大到新环境、新租户或新依赖。

- **范围**：D01–D08通常一次影响隔离环境一个实例或一条依赖链路；DB/Redis切换由管理员单独操作。D07/T27通用故障域检查可由D11跨AZ记录承接；D09共享依赖、D10入口、D11 ADS/AZ、D12 Region是明确扩展范围，必须逐项列三服务/平台资源ID及独立管理观察通道，不能临场扩大。
- **时长**：5分钟稳态基线；常规故障注入60秒，部分用例30秒/15秒依正文；可撤故障规则上限120秒，撤销后至少10分钟观察并完成对账。平台/数据切换按管理员确认的分阶段期限执行。D12主权隔离屏障不属于故障规则，不随TTL撤销；提升后的超时处理为保持安全单写并停止扩流，不是自动逆向提升或回拨DNS。
- **自动停止**：触及任一资源安全线、观察流控制/恢复超签认期限、出现重复终态/双写/越界或失去目标监控，立刻停生成器和扩流、撤销可撤故障；故障规则TTL独立于被测进程。Region写权保护屏障继续保持，由IC/DBA独立决定后续，故障网络恢复也不能让旧主自动获得写权。执行人与观察人不能是同一个自动化任务。
- **双重撤销**：注入前在空载目标验证“创建故障规则→查询范围→撤销→健康检查”，失败不开始；观察人持有独立撤销操作。D12另验证“故障规则撤销/旧域重连后主权屏障仍生效”，不能把解除故障和解除保护合并在finally中。
- **观察负载**：另租户每10秒普通Run、每30秒Stop，加一个quiet WS和状态查询；内部回调按用例发送。D09–D12增加agentService管理模块可信映射读取、agentService转发模块可对账测试任务、Relay和三服务状态探针；只有当前合法主Region可执行测试写入/外呼，备Region只做不会产生业务副作用的准备验证。
- **恢复阶梯**：撤销故障后先停止重试/恢复突发，维持观察流；确认治理推进后依次恢复测试目标负载的25%、50%、100%，每档观察2分钟，失败退回上一档。百分比以本次已测安全负载为基数，不代表生产容量。
- **证据**：统一保存时间线、故障规则命中/删除、配置与artifact、状态对账、资源峰值和结束值；开始/结束/异常终止都记录。D编号关联所有实际执行T编号，未执行的子场景不得随整次演练填PASS。

### D02 — 数据库连接、DB/JVM锁、事务回滚与治理竞争

**目标/关联：** T02/T07/T13/T23/T38，R38 / RB02/RB03。DBA负责真实openGauss与锁/连接，应用负责SQL/异步事务边界、JVM monitor和回调，SRE独立观察，测试保存正确性证据；新增T38子项NOT_RUN。

6. 子场景E分别验证锁等待超时、真实触发的死锁受害事务、SQL超时、客户端取消及异步线程切换：核对事务整体回滚、连接/锁释放和缓存未暴露未提交事实，受保护观察流继续；未触发的分支如实NOT_RUN，不能通过直接改库补出预期状态。

### D10 — WCM备用源与ALB/GSLB入口

**目标/追踪：** R31/R32 / T31/T32 / W12 / RB12；[DEP04](deployment.md#dep04)、[DEP03](deployment.md#dep03)。WCM/静态托管/前端负责人、ALB/GSLB负责人操作，应用负责人验证业务。初始NOT_RUN。

1. 将同一已验证静态manifest、运行配置和上一兼容版本预发布到独立非ADS托管源及对象存储，实际跑过备用接入的TLS、文根、深链接和完整页面；确认静态切源不会悄悄修改业务写Region。对象存在但未接入时禁止开始WCM主源故障实验。
2. 子场景A只阻断测试WCM60秒，按DEP04切备用源；分别从新浏览器和旧缓存浏览器访问入口、懒加载、深链接、登录后的API、WS及测试Run。恢复WCM后按DEP04验证再受控回切，记录两个方向的版本一致性，禁止自动来回抖动。
3. 完全复位后子场景B逐项注入单chunk404、旧HTML/JS不匹配、错误缓存和静态运行配置；每次单一错误，确认错误能被合成探针发现，已预发布兼容版本能恢复，主业务API不会被SPA 200遮盖。
4. 完全复位后子场景C从三服务完整路由表逐项测试错误文根、重写、健康摘流、WS Upgrade、SSE idle及POST响应丢失；验证身份/租户/回调ACL及重试副作用，保留实际后端、请求路径和状态记录。
5. 区域ALB不可达子场景先核对是恢复当前ALB还是需要业务Region接管。后者必须先通过D12的隔离/提升/验收门槛，再操作GSLB/DNS；测试旧DNS缓存、旧WS、请求重试仍到旧Region时安全拒绝，及全部目标不健康时fail-open/兜底不会绕过备用禁写。禁止独立D10实验把两Region同时开写。
6. 观察至少10分钟完整浏览器业务、流式事件、DNS实际解析和连接恢复，不把DNS控制台显示变更成功视为全客户端生效；统计静态、入口、业务恢复分别耗时。

**注入/停止期限：** 规则默认60秒/上限120秒；实际切源、DNS收敛受签认`D_static/D_entry/D_dns`。指向错误目标、API返回静态内容、重复副作用或备用源依赖故障ADS时立即停止切流并隔离错误配置。

**撤销与证据：** 恢复明确的静态/ALB版本和注入通路；仅静态主备可独立受控回切。业务写权已改变时按D12回切，不自动拨回原DNS。保存主备manifest、对象版本、ALB/GSLB配置diff、浏览器网络、实际Region及副作用对账，前端/入口和应用共同签认。

### D11 — ADS运行面、控制面与跨AZ剩余能力

**目标/追踪：** R33/R34 / T33/T34 / W13 / RB13；[DEP02](deployment.md#dep02)、[DEP03](deployment.md#dep03)。ADS/SRE操作，三服务、DBA/缓存及测试独立观察。初始NOT_RUN。

1. 将三服务副本、ALB后端、宿主/容器、DB/Redis、镜像/配置/凭据和网络依赖映射到真实Region/AZ；标出独立管理通道与失去一个AZ的安全容量。P中每Region至少两AZ目标若未落实、服务仍集中单AZ或剩余资源不足，先整改布局/限额，不在未知范围直接实验。
2. 子场景A终止专用容器/宿主或隔离其运行通路60秒，验证ALB摘流、ADS实际恢复与旧owner拒写；Runtime重建后不能可靠接管的Run按确定合同收口，保留远端任务对账。
3. 完全复位后子场景B分别使测试控制面、镜像仓库、配置/测试凭据依赖不可用60秒；分开观察存量业务和发布/扩缩/重建能力。若只阻断操作客户端到控制面的网络，报告只能证明该通路失联行为，不能宣称真实ADS控制面宕机已验收。
4. 完全复位后子场景C按已登记集合隔离一个测试AZ，三服务混合负载从已测安全容量25%、50%、100%阶梯验证；应用AZ故障与DB/Redis同AZ故障分别执行，数据层由管理员操作。确认ALB不会持续向失效AZ转发，观察剩余AZ的DB连接、Redis回源和控制任务。
5. 撤销故障后逐批回接原AZ，验证镜像/配置/凭据和服务身份，检查瞬间重连、租约冲突及旧Runtime副作用；回接完成不等于UNKNOWN任务自动解决。
6. ADS整个Region运行面故障超出区域内恢复目标时，只按D12启动区域接管；确认备RegionADS控制/运行能力和非ADS静态备用均不依赖故障域。原Region平台恢复后仍保持其写权隔离，直到正式回切。

**注入/停止期限：** 实例/通路规则60秒/上限120秒；AZ集合和依赖切换必须有管理员独立恢复操作。资源超线、实际影响跨出集合、独立观察失联或控制路径失效立即停止扩流并撤销故障，域级接管保护不随之解除。

**撤销与证据：** 平台恢复控制/运行资源和路由，不重建未知外部任务；保留实际容器/宿主/Region/AZ ID、平台事件、镜像digest、三服务业务与剩余容量、回接峰值和任务差集。ADS/SRE与三服务确认完整恢复边界，模拟与真实平台故障证据分开。

### D12 — 双Region写权接管、分区安全与回切

**目标/追踪：** R35 / T35 / W14 / RB14；[DEP05](deployment.md#dep05)、[DEP06](deployment.md#dep06)。IC指挥，DBA负责恢复点/数据角色，业务附件存储负责人核对对象，ADS/入口负责运行隔离/GSLB，三服务与下游负责后台/外呼/UNKNOWN核对，测试独立记录。初始NOT_RUN。

1. **建立基线与执行门槛**：固定本轮初始A主、B热备，确认三服务和第三方流向、两Region独立ALB/ADS及实际DB异步复制；B不允许业务写/外呼。预置每秒提交标记、agentService管理模块映射版本、agentService转发模块/DomainAgent回执、Relay任务、Chat FULL/no-store及对象引用，记录复制位置和丢失容忍目标。无可验证旧主隔离机制则不进行开放B写入的子场景。
2. **单写屏障预演**：空载测试验证即使A仍活着、旧DNS/长连接仍到A、定时器/回调到达，旧DB写端与三服务外呼都能被可靠阻止；验证撤销网络故障或管理工具退出不会解除屏障。若能力缺失，安全拒绝接管这项可以有证据，整体容灾放行仍BLOCKED。
3. **计划接管子场景**：按DEP05暂停新写并登记在途，执行旧应用/外呼和旧DB写端隔离，独立观察人验证后IC签认；DBA/存储负责人核对B数据库及业务附件对象恢复点、未复制提交、对象版本/内容、DB文档引用与租户/访问权限。门槛通过后才由DBA提升B；损失在批准范围且受影响功能已隔离才放行符合条件的业务。静态manifest通过不能替代业务附件核对；超批准RPO或不可核对时阻断，不因倒计时提升/放行。
4. **激活及入口**：B三服务指向同一合法数据端点，检查agentService管理模块映射、agentService转发模块副作用保护、Relay会话语义、Chat治理和Redis状态恢复；受控验证通过后仅开放B新写，再切GSLB/DNS。按25%/50%/100%恢复负载，旧入口持续验证拒写，静态页面按DEP04保持可用。Runtime中断不能靠自动重跑伪装接管成功。
5. **分区/复制滞后子场景**：完成安全状态确认后独立演练A仍存活的分区、DB复制滞后60秒，以及DB文档引用已复制而业务附件对象未复制三种情况；按相同接管顺序验证。对象缺失或权限无法核对必须阻断相关放行；批准损失仍列对象/引用差集并隔离受影响附件功能，不得报全功能恢复。网络规则最多120秒撤销但主权屏障不失效；旧主无法隔离则B禁写，记录RTO未满足与安全边界有效，不能填整体成功。
6. **旧域重连与迟到副作用**：恢复A网络而不恢复其写权，发送旧DNS请求、旧连接帧、迟到Stop/async callback及排队的agentService转发模块命令；验证无法导致旧主写入、B新Run错误取消或重复外部执行。远端结果未知保持UNKNOWN，联合下游查询/人工对账，不把缺少本地记录解释为未执行。
7. **受控回切子场景**：按DEP06修复A并预先追平；05预收集水位后，在QUIESCING阶段注入迟到callback/终态提交，证明该水位仍会变化。06强制隔离B数据写入及外呼，07取得或证明**隔离后的最终提交位点**，等待A追平并核对隔离前迟到提交已包含、隔离后写入被拒，连同业务附件对象恢复点、DB引用/权限通过后才08激活A；受控业务验证后改入口。提前追平不能替代最终检查。失败按13处置：B未失权继续B；B已隔离/A未激活先证明无人写再恢复B；A已取得写权必须重新转移才能恢复B，不自动回切。
8. **收尾**：按当前唯一主Region重建跨区复制及热备状态，记录所有服务恢复、遗留任务核对和灾备能力恢复时点；对账FULL有效恢复点内事件、no-store不可恢复结果、agentService管理模块映射/对象引用和外部副作用。确认没有未解释的重复/双写，剩余UNKNOWN与已允许损失均有负责人和处置结论，才结束。

**注入/阶段期限：** 可撤网络故障默认60秒/上限120秒；接管/回切按执行单`C_cutover/C_failback`，包含复制滞后、隔离、提升、三服务检查、DNS实际收敛及观察。时间为测试约束，实际RTO/RPO需要测量，不写成承诺；保护屏障无自动到期。

**中止/恢复：** 提升前失败可在确认仍只有A写权且数据角色未变化时恢复A入口；提升后尤其B已写入时，禁止简单回滚DNS、旧凭据或旧数据库角色，只能保持B单写或另走DEP06受控转移。双写迹象出现即停止新增业务写入与测试生成器，保留证据，由IC/DBA确认可证明安全的唯一写端；规则撤销不撤保护。

**必交证据：** 阶段签认/隔离回执、预收集水位与隔离后最终提交位点、目标追平证明、QUIESCING迟到提交及双端拒写探针、复制标记差集、业务附件对象恢复点/版本/缺失与DB引用/权限核对、批准损失及被隔离功能清单、agentService管理模块映射/静态manifest、远端执行次数/UNKNOWN、GSLB实际流向、三服务资源峰值及五种恢复时间。仅完成首页切换、DB提升或本地mock不能关闭R35；受限功能尚未恢复时不得报告全功能恢复。

## 5. 结果、复盘与上线门槛

每次演练形成一条不可被后续成功覆盖的记录：`D编号 / 子场景 / T编号 / artifact与配置 / 环境 / 执行人 / 状态 / t_detect / t_contain / t_fault_removed / t_service_recovered / t_backlog_reconciled / 失败数 / 丢失数 / 重复数 / 资源峰值 / 证据位置 / 未关闭问题`。故障发生但无法检测时记录检测缺口，不能省去发现时间。

判定成功必须同时满足：故障范围受控、自动/人工撤销有效且未撤掉主权保护、正确性断言通过、资源有界且归还、服务及遗留任务在签认目标内恢复、运行册能由另一名值班人复现。跨Region还必须唯一有效写主、实际RPO与损失集可解释、旧域恢复不自动写入、未知副作用不盲重跑。超出资源线而安全终止属于FAIL并保留证据；环境不具备或协议未确认属于BLOCKED。

复盘由相应负责人将失败项关联到风险与加固任务，注明责任人、完成条件、复测编号、到期日。整改后只重跑受影响用例与必要回归，但不能删除首次失败记录。R05、R19、R22等联合条件未验收，生产openGauss/实际Redis拓扑差异未覆盖，或关键SLO/恢复目标未签认时，不能以本地测试通过解除上线限制。

上线前交接必须提供真实ALB/GSLB规则、WCM与独立静态备用接入、ADS操作、三服务状态查询、监控/日志、单写隔离证明、数据恢复/回切步骤、回滚包和联系人。T28–T38的风险/加固/运行册/演练完整矩阵见[部署新增追踪矩阵](tests.md)；每项关闭须由相关服务及平台联合签认，不能只签ChatService。本文件给出操作行为及验收合同，缺失的动态开关、指标、drain、对账与平台控制能力必须先落地验证，不能由值班人员在事故中自行发明。
