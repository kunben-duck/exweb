# 运行稳定性测试与验收

源码基线：`8f48d6cc084be91bcbaad90be43dac7181636cb4`；本轮文档起点：`975db466`；日期：2026-09-22。本文收敛为21项高影响运行风险的测试规格，全部为 **NOT_RUN**，不表示整改或演练已完成。历史记录继续保留原基线，见[验证证据](evidence.md)。唯一风险/工作包/责任追踪表见[风险登记](risks.md#risk-register)，本文不再复制一套矩阵。

当前ChatService、relayService、agentService共用共享DB（openGauss）和Redis；agentService同时承载管理、技能查询、统一chat与MCP。两条执行链分别为`ChatService→agentService统一chat→DomainAgent`和`ChatService→relayService→agentService MCP→下游`；intentService（第三方）独立。adminService/toolService/agentService拆分、文件worker及跨AZ/Region目标未落地前，不能当成已有隔离能力。

## 1. 公共执行合同

- **环境分层**：L1确定性夹具/并发测试；L2与生产版本、存储类型、索引、驱动、隔离级别一致的openGauss及实际Redis拓扑；L3多实例及真实测试下游；L4平台/跨服务/容灾联合验证。开发PostgreSQL、Redis standalone和本地mock不能替代生产对应验收。
- **负载与窗口**：专用租户/用户/对象前缀；5分钟无故障基线，1/4/8并发各2分钟，安全线前才增加档位；注入默认60秒、最长120秒，程序屏障最长30秒并在`finally`释放。撤销后至少观察10分钟，长稳态用例另列；这些是测试窗口，不是已承诺SLO。
- **观察流**：另一租户每10秒一次正常聊天、每30秒一次Stop，并观察heartbeat、Watchdog和状态查询。记录到达率、实际在途数、成功和过载拒绝；拒绝不能算成功吞吐。
- **安全停止**：任一资源越线、观察流/控制链路超出签认期限、出现重复执行放大、影响越界或无法撤销时停止增压并撤故障，按[运行册](operations.md)恢复。无需实际造成OOM才证明风险。Region写权/外呼隔离屏障不随注入TTL撤销。
- **公共清理**：撤规则→释放屏障→关闭测试连接/任务→核对Run及远端残留→确认资源回落→仅清本次数据。每例同时覆盖完成、错误、超时、取消和实例退出；无法安全覆盖的分支记录BLOCKED/NOT_RUN，不能写PASS。

执行前由应用、DBA、SRE、下游与测试负责人在执行单签认具体数值；缺失时相关容量或恢复结论为BLOCKED，可先验证不依赖该值的行为。

| 预算/目标 | 必须记录的范围 |
|---|---|
| `B_heap/B_rss/B_direct/B_cpu/B_threads/B_fd/B_disk` | 容器/JVM安全上限、诊断及回滚余量；CPU同时记录quota、节流与GC，不以单一利用率判断 |
| `B_queue_events/B_queue_bytes/B_body_bytes/B_upload_bytes/B_temp_bytes` | 队列、累计正文、接收文件与临时盘预算；未实现的上限标缺口，不伪称已有配置 |
| `B_db_all/B_redis_all/B_service/B_control/B_replay/B_pool` | 所有服务及最大/滚动重叠副本的连接、队列、并发与治理余量；注明本机/服务/集群作用域 |
| `D_request/D_stop/D_release/D_recovery` | 逻辑请求、取消、真实底层资源释放、服务恢复及遗留任务收口期限，分别测量 |
| `S_accept/S_first/S_complete/S_resume`、`Δsteady` | 受理、首有效事件、完成、恢复目标；恢复后资源允许波动，不允许积压持续增长 |
| `A_call/D_locate/D_ack/D_handoff` | 一次逻辑请求跨层总尝试数，以及定位、接报和交接期限 |
| `D_static/D_entry/D_az/D_region/D_reconcile`、`RPO_*` | 平台恢复目标及DB、配置、业务附件对象实际恢复点；接管/回切阶段期限与DNS收敛另列，不能假定RPO=0 |

<a id="joint-localization"></a>
### 定位、释放与恢复的共同断言

每例归档环境/版本、配置脱敏快照、负载、注入及撤销时刻、实际资源峰值、恢复时间与`PASS/FAIL/BLOCKED/NOT_RUN`。保存`traceId/parentCallId/runId/skillId/远端操作ID/配置版本/服务与阶段/状态码/耗时/尝试数`；字段未具备时登记观测建设任务，不补造下游日志。HTTP错误、流内错误、本地终态与远端事实分开，超时只能证明边界超时，不能直接归责DomainAgent内部。

通过线程/JFR、HTTP/JDBC/Redis会话及任务记录证明timeout/cancel后底层工作、连接、timer、订阅、许可和临时文件已释放，而不只证明`Mono`完成。解除故障后保留旧积压，以25%/50%/100%已测安全负载各2分钟恢复，随后观察至少10分钟；正常聊天和Stop可推进、积压消退且资源无持续增长才通过。

FULL仅承诺实际恢复点内已持久化数据的补读；no-store不新增正文持久化。Runtime不具备可靠断点执行接管，UNKNOWN先查询/联合对账，禁止通过自动重跑制造恢复峰值或重复副作用。状态核对用于证明任务收口及资源释放，纯业务正确性/安全专项不在本轮主清单展开。

## 2. 21项活跃用例

<a id="t01"></a>
### T01 — 快流慢库与累计正文（R01；L1→L3；RB01 / D01）

- **配置/负载**：Relay和统一chat各测FULL/no-store；1/4/8 Run，每流10/100/1000帧每秒、1KiB/接近协议帧上限两档，并累积长正文。
- **注入**：落库每批延迟200ms，再完全阻塞30秒，保持下游发帧；分别完成、错误、Stop、总期限到期和退出实例。
- **验收/证据**：加固后队列事件数、字节和正文不越预算；超限明确失败且收口，观察流达标；订阅/连接/许可在`D_release`释放。保留堆/JFR分配、源/库/客户端速率及当前BUFFER增长证据，不预设现状通过；清理依公共合同。

<a id="t02"></a>
### T02 — Resume、慢客户端及恢复风暴（R02；L2→L3；RB06、RB09 / D05）

- **配置/负载**：1千/1万/10万事件历史，1KiB与近帧上限分别测；session SSE、Run Resume、WS各覆盖1/4/8连接，再到签认`B_replay`及超限一档。
- **注入**：补读期间继续输出；断网30秒后多页签同时恢复；分别在commit前、commit后publish前退出一个实例，取消补读；模拟错误地反复`afterSeq=0`。
- **验收/证据**：分页/衔接缓冲和回放字节有界，恢复超额拒绝可见，首事件/Stop不被挤占；恢复点内保序补读，no-store明确缺口。关闭订阅后FD、注册项、DB扫描和live buffer回落；停止方退出后的遗留任务可在`D_recovery`收口。保存游标/查询量/积压/资源与任务对账，不以重新发Run代替恢复。

<a id="t03"></a>
### T03 — 鉴权、池等待与全链路期限（R03；L1→L3；RB05 / D04）

- **配置/负载**：实际token resolver、HTTP池、线程池与取消能力入册；Intent流式/阻塞、候选、用例库、标题和WeLink按启用情况分别测1/4/8并发。签认`A_call/D_request/D_release`。
- **注入**：外部鉴权/HTTP池故障注入60秒、DNS/连接黑洞、401/429/503分别执行；程序阻塞夹具最长30秒，外层超时后仍执行的测试任务须在夹具总上限内释放；返回结果丢失时观察是否重复执行。
- **验收/证据**：记录入队→鉴权→借连接→发送→有效事件→超时→实际退出；逻辑总期限覆盖排队与重试，底层残留和队列有界，非幂等UNKNOWN不盲重放。当前Intent流式鉴权5s仅是外层保护，阻塞兼容模式HTTP5s不保证覆盖同步token获取；企业resolver内部期限未知即保留缺口。保存attempt/auth次数、任务与池时序，释放全部夹具后核对正常聊天/Stop。

<a id="t04"></a>
### T04 — Redis接收线程与消息风暴（R04；L1→L3；RB01、RB04 / D03）

- **配置/负载**：两Chat实例及实际Redis拓扑，1/4/8 topic后逐级提升到接收预算；记录listener真实执行器、队列和拒绝策略。

- **验收/证据**：线程、队列事件/字节、CPU和堆有界；拒绝产生明确恢复信号，FULL受控补读/no-store记录缺口，不能静默忙循环重连；订阅和线程回落。保存入站率、池/GC、重连/拒绝与观察流时序；停止专用发布者并撤销断网。

### T05 — 长历史、复杂查询与旁路争抢（R05；L1→L3；RB02、RB03 / D08）

- **验收/证据**：查询规模、CPU/堆、排队龄、SQL和连接等待受限，许可覆盖实际完整工作；超时后迟到JDBC不继续无界堆积，辅助失败不拖垮Stop/heartbeat。撤屏障、停突发后确认任务/队列回落，保存SQL计划/行数、线程池、租户map及分配趋势。

### T06 — 500MiB文件、慢存储与生命周期（R06；L1→L3；RB07 / D06）

- **配置/负载**：记录4C4G或实际规格、堆/direct、临时卷、multipart、ALB与provider限制；当前文件50MB/请求60MB及应用50MiB先测拒绝。W06实现后才测1/10/50/500MiB及上限+1字节，先1并发再按字节预算增至4/8；不得直接运行32×500MiB。API Store整份byte[]与对象存储SDK分开验收。
- **注入**：无可信Content-Length、慢上传/下载16KiB/s持续60秒再取消；临时复制/SDK上传延迟、存储成功后DB登记失败、下载取流后暂停30秒、退出实例分别测；专用临时卷只填到安全停止线。
- **验收/证据**：接收前准入和在途字节、盘、FD、连接有界；下载许可覆盖流生命周期，超时/取消真实复制/SDK任务在`D_release`结束。API Store HTTP30s从整文件读取后开始，对象存储连接10s/socket30s不是完整传输总期限，SDK重试需另核验。500MiB支持须完整传输及慢流取消均通过。
- **目标路径/清理**：对象存储直传验证文件字节不经过Chat/技能查询进程，完成通知丢失不触发整文件重传；EDM独立worker验证队列字节/年龄与退出恢复。灰度回退不得把500MiB导回旧`readAllBytes()`路径。按对象与DB引用核对后清理未完成分片/无引用对象，不清有效对象；保存每阶段字节/资源/任务时间线。

### T07 — CPU、JSON、日志与JVM压力（R07；L1→L3；RB02 / D01）

- **配置/负载**：记录JDK、堆、direct、容器quota和实际解析限制；按协议有效上限测试大帧、深层JSON、高频小帧、长正文与高频错误日志，禁止无边界生成器。

### T08 — 探针、灰度、摘流与发布恢复（R08；L3；RB08 / D07）

- **配置/负载**：至少两实例，经ALB和saas gateway（SaaS统一网关）；准备镜像/配置回退及实际探针。持续Run、WS、Resume、async/Stop和治理混合流；未具drain/回滚能力即BLOCKED。
- **注入**：一实例失去DB60秒，对比health与业务；复位后先摘流正常退出，再单独异常退出。灰度共库时跨新旧实例发送Stop/回调/恢复，后台同时扫描；单独验证错误profile导致协调key/topic分裂。DBA只在隔离库施加兼容扩展DDL/锁等待，另验证新版本写入后旧版本回退。
- **验收/证据**：依赖故障不触发全实例重启；摘流停止新准入且后台Run有界排空/收口；新旧版本共享正确协调域、DDL不让旧SQL长期阻塞。应用回退不自动收缩DDL或删除灰度数据。撤注入后核对版本、任务、连接和积压；保留真实路由/探针/锁/回退记录。
- **运维子项**：实际备份恢复到全新隔离库并测恢复点/耗时；测试凭据/配置轮换造成的短时不可用按现有协议测，记录共同故障域，不能推定平台已有动态刷新。纯安全证书正负例另行专项。

### T09 — 共享DB（openGauss）与治理预算（R09；L2→L4；RB03、RB11 / D02、D09）

### T10 — 共享Redis故障与回源风暴（R10；L2→L4；RB04、RB11 / D03、D09）

- **配置/负载**：先列三服务缓存、Pub/Sub、锁、队列及不可重建状态；实际Cluster/主从拓扑及容量入册。

- **验收/证据**：CPU/内存/连接和DB回源有界；Pub/Sub不承担历史恢复，FULL受控补读，no-store缺口可见；锁/持久状态按各服务实际合同恢复。撤故障后逐批预热/订阅，核对三服务状态及积压，保留用途表、切换时间线和资源峰值。

### T11 — WCM故障与独立静态备用（R11；L4；RB12 / D10）

### T12 — ALB与saas gateway入口故障（R12；L3→L4；RB12 / D10）

- **前置/注入**：取得真实ALB文根和saas gateway（SaaS统一网关）鉴权、连接/idle/请求总限与重试配置；逐项注入错误路由、上游慢转发、WS Upgrade失败、SSE截断、POST响应丢失60秒。
- **验收/证据**：定位到实际失败边界，网关重试不放大有副作用请求；受控重连且后台任务不因断连无界累积。三服务API/WS/内部回调仍按合同可达，入口限额保护正常聊天/Stop，配置未知不写成应用默认值。
- **清理**：恢复已验证规则并观察10分钟；Region入口故障需转移写权时必须先T15门槛，不能单独切DNS开双写。保存规则diff、连接/重试计数、资源与后台残留。

<a id="t13"></a>
### T13 — ADS运行面与控制面（R13；L4；RB13 / D11）

- **前置/注入**：实际容器/宿主、管理通道、镜像/配置/密钥依赖入册；逐个终止测试容器、阻断运行通路、控制面、镜像仓库或配置依赖60秒，完全复位后换子项。

- **清理**：恢复资源和路由，逐服务核对Run/远端任务与连接，保存平台事件和镜像digest；Region级故障按T15，不自动恢复旧域写权。

<a id="t14"></a>
### T14 — 单AZ失效与剩余容量（R14；L4；RB13 / D11）

- **前置/注入**：两AZ实际拓扑与失去一个AZ后的安全容量确认后，以25%/50%/100%安全负载分别隔离一AZ应用60秒；数据层同AZ故障独立由管理员操作。
- **验收/证据**：剩余AZ完整业务链、Stop和治理达标，ALB不持续转发至失效AZ，DB/Redis/下游配额不被放大；容量不足必须受控拒绝并记录未达SLO，不能靠副本数推定容量。
- **清理**：逐批回接，验证重连/缓存预热/遗留任务无二次洪峰；保存AZ请求分布、连接峰值和恢复时间，拓扑/撤销能力未知则BLOCKED。

<a id="t15"></a>
### T15 — Region接管、网络分区与回切（R15；L4；RB14 / D12）

- **前置**：A主B热备，三服务旧DB写端、后台及外呼隔离可独立验证；B禁写。登记每秒提交标记、配置、Run/远端任务及业务附件引用，签认实际RPO与阶段期限。能力未实现不得开放B写入实验。
- **注入/步骤**：分别计划接管、A仍存活的分区、复制滞后60秒、业务附件对象落后、A重连和迟到命令。严格按[DEP05](deployment.md#dep05)：隔离A→确认数据/对象恢复点→提升B→验证服务→开放符合条件业务→切全局入口。故障TTL撤销不解除隔离屏障。
- **验收**：始终唯一有效写Region；隔离无法确认则B禁写。FULL受恢复点限制，no-store不新增正文，Runtime不自动重跑UNKNOWN。B资源、重连与恢复积压受控；附件对象未到或损失超批准RPO阻断相关功能放行，不能报全功能恢复。
- **回切/证据**：按[DEP06](deployment.md#dep06)预先追平，隔离当前B写入/外呼后取得最终提交位点，再验证A追平及附件引用后转移写权；提前水位不替代最终检查。失败维持最后可证明的安全单写状态，不仅拨回DNS。保存隔离/拒写回执、最终水位、损失/UNKNOWN、资源及恢复时间；重建复制/热备后才结束。

<a id="t16"></a>
### T16 — 一体agentService与技能配置依赖（R16；L3→L4；RB05、RB11 / D09）

- **配置/负载**：四模块真实CPU/堆/线程/HTTP/JDBC池和限额入册，管理、技能miss、统一chat、Relay MCP各1/4/8并发轮流增压；两条链同时保留观察流。
- **注入**：worker阻塞30秒、慢HTTP/SQL/Redis与429各60秒，终止一个agentService实例；单故障通过后组合技能回源＋MCP突发。技能HTTP默认2s无自动重试、缓存10m；验证缓存失败回源且2s不覆盖缓存/排队。
- **验收/证据**：单模块不耗尽其余模块/三服务资源；留存策略启用时配置不可用阻断执行，仅附件检查失败开放按当前合同区分，不能把关键查询统一降级。记录映射/缓存变化引发的错误调用或重试负载，未知结果不重放。拆分后按相同总配额与逻辑负载复测，不能将增容效果算作拆分收益。
- **清理**：恢复实例、映射和屏障后，先配置/治理再chat/MCP、最后管理旁路；保存模块×资源×受影响链路、远端任务和定位证据。

<a id="t17"></a>
### T17 — MCP扇出、嵌套重试与取消残留（R17；L3→L4；RB05、RB09 / D04）

- **配置/负载**：Relay、agentService和工具方先提供真实扇出/尝试/期限/取消及状态查询合同；1/4/8 Run，每Run1/4/8工具，只到安全预算档位。
- **注入**：在Relay→MCP、MCP→下游分别黑洞、429/503、已接收后丢响应/断流60秒；部分分支排队/执行时Stop，令一个可撤底层任务忽略取消30秒。
- **验收/证据**：逻辑Run、工具调用、尝试与实际执行四层计数，跨层总量不相乘失控；本地收口/远端停止/UNKNOWN分开，线程、连接、队列与许可按`D_release`回落；其他技能和Stop可推进。当前外部内部能力未知不能用Chat mock关闭；未来拆分另测新增网络/鉴权段。
- **清理**：停新扇出，逐执行方结束测试任务再撤规则/清数据，保留父子调用树、放大比、残留及恢复峰值。

<a id="t18"></a>
### T18 — DB/JVM锁、长事务与阻塞传播（R18；L1→L3；RB02、RB03 / D02）

- **前置/负载**：按实际SQL/线程列出受理、事件追加、Stop/终态、交互、回调、批删、绑定/治理的事务和显隐式锁序；两实例、同Session与不同Session对照，每个实际相交候选20轮。保留Session排序加锁等现有保护，不预判存在死锁。
- **注入**：两个真实事务在首个加锁SQL后各设可释放屏障，再交错下一锁；实际无相交/无环写明结果。单独测持锁期间Redis慢60秒、批删/DDL等待、SQL超时及外层取消但JDBC仍执行。JVM测试同topic慢订阅、WS替换/dispose、Relay发送/关闭，屏障最长30秒且有外部独立释放机制。
- **验收/证据**：真实DB等待图/SQLSTATE、JVM monitor owner/waiter及回调栈共同区分死锁、锁等待、线程池饥饿；人为反序夹具只证明诊断机制。期限后事务完整回滚，锁/连接释放，后台治理/Stop不中断；仅对安全幂等且已证明回滚的完整事务有界重试，不重试中间SQL或外呼。
- **清理**：`finally`释放屏障并回滚登记事务、关闭订阅，核对线程/池/许可回落；记录同步/异步线程的实际事务/连接ID，不能用注解或客户端异常推断已回滚。

<a id="t19"></a>
### T19 — DomainAgent异常与统一chat拖累（R19；L3→L4；RB05 / D04）

- **配置/负载**：真实`Chat→agentService统一chat→DomainAgent`两跳配置和日志，故障skill与健康skill各1/4/8 Run；记录Chat默认原始chunk空闲300s、订阅起总限15m、无应用重试、帧256KiB与并发64，旧TIMEOUT覆盖须按实际值登记。
- **注入**：分别在agentService→DomainAgent黑洞、429/5xx、首帧前/后断流、持续原始chunk无有效事件、高速大帧各60秒；本地机制用缩短配置测试，默认长预算另签独立执行窗口，不以短测冒充默认期限通过。
- **验收/证据**：有界隔离到skill/下游，健康技能/Stop可用；流和正文不因异常输入压垮CPU/堆；技术故障不无条件重放或切Relay。逐跳标明HTTP/流内错误、有效首事件与最终状态，agentService内部重试未知保持缺口；恢复后旧请求不形成洪峰。
- **清理**：恢复下游后先查未决操作，确认实际任务与连接结束再放量；保存跨跳调用数、错误来源证据、资源和定位耗时。

<a id="t20"></a>
### T20 — intentService重试与Relay降级洪峰（R20；L3→L4；RB05 / D04）

- **配置/负载**：Intent关闭/STREAMING/BLOCKING及RELAY_FALLBACK/FAIL_RUN分别测；启用默认最多4次调用（首次＋3重试，主路由无退避），流式鉴权5s/首有效事件5s/空闲30s/每次HTTP流120s。候选支路另核验5s单次与200ms–1s指数退避抖动，不能将其策略当主路由策略。
- **注入**：独立第三方黑洞、429/5xx、协议错误和首帧后断流60秒，1/4/8逻辑请求逐级增加；再模拟成功恢复时积压重试同时释放。
- **验收/证据**：每逻辑请求attempt/auth次数符合当前配置，120s不是含全部鉴权/重试的逻辑总限；加固后统一总预算/重试节奏与降级配额可验证。RELAY_FALLBACK不能冲垮Relay及其共同依赖agentService，FAIL_RUN明确失败且资源释放，NO_MATCH不技术重试。记录有/无意图路由的实际容量，拒绝不美化SLO。
- **清理**：撤错误规则，保留积压按档恢复，核对Intent/Relay/agentService调用率与Chat/Stop资源回落；不能仅看Intent恢复200判定通过。

<a id="t21"></a>
### T21 — relayService半开、断流及取消残留（R21；L3→L4；RB05、RB09 / D04）

- **配置/负载**：真实Relay，1/4/8 Run及同session后续Run；记录TCP5s、Upgrade/config各10s、心跳20s/入站无响应90s、Run30m、Stop确认5s、无应用重试，60s idle仅临时Stop连接。
- **注入**：连接拒绝、握手黑洞、无ready、已连接半开、无终态断流各60秒；分别在Stop发送前后丢响应、让底层工具继续30秒、延迟旧session级Stop15秒并交错后续Run；短期限机制验证与默认长期窗口分开。
- **验收/证据**：坏连接/订阅/心跳/许可按期限回收，健康链和Stop不受拖累，无重连风暴；发送完成或paused可使本地确认完成，**不证明所有工具已停**。本地与远端状态分别核验，迟到Stop不能引发下一Run错误重试放大；无代次/顺序或查询证据就保留联合缺口，不能只凭mock关闭。
- **清理**：恢复链路，逐session/工具核对仍运行任务并有序停止，再恢复新调用；保存连接/命令/工具时间线、残留数和恢复后资源。
